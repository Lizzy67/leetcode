AGENT · TOOL CALLING

工具结果引用：让模型写「引用」，让 Runtime 填「真值」

上一个工具的结果不再由模型抄进下游参数，而是写一个引用 ${resultId.path}； Runtime 在工具执行前从工作记忆取出真值、按需转换结构、校验合法，再去调用工具。 真值不经模型之手，存量工具一行不改。

01

为什么要做

串行工具链里，下一个工具的参数常常来自上一个工具的结果：文件 URI、对象 ID、大段文本、一整个列表。 这些值现在要先整段塞回模型上下文，再由模型原样抄进下游参数——长 URI 抄着抄着就断了； 结构不一致时，还要模型手工改写大段 JSON。抄写和改写，模型都做不稳，而且每一轮都在烧 Token。

抄不准：长值复述易截断、改写、漏字符 太昂贵：大结果反复回灌，输入 Token 和时延一起涨 改不动：结构适配靠模型改 JSON 或逐个改工具，都不划算
02

方案主链路

Reference → Resolve → Invoke，全部发生在工具执行之前
工具 A
结果入库
返回结果默认写入工作记忆，得到短标识 resultId
Runtime
按 Policy 送模
命中 mask policy 的字段换成引用，其余内容全量可见
模型
只写引用
下游参数填 ${resultId.path}，可见与否都不复述真值
Runtime
求值 · 转换 · 校验
查工作记忆回填真值，按参数策略适配结构，验完 Schema 与权限
工具 B
真值执行
校验通过才调用；结果再入库，链路闭环
03

两种场景

按「模型要不要看到这个值」分流，殊途同归于引用
场景一 · 可见但引用

结果全量进上下文，参数仍写引用

模型需要读内容才能决策：工具返回原样进入上下文，正文、结构、字段都可见，推理照常。 唯一的约束是——把这些值传给下游工具时，参数里写 ${resultId.path}，不许把看过的内容再抄一遍。

上下文：text = "血糖偏高，建议…"（全量可见）
模型出参：report(content = ${e5f6a7b8.text})

「看」与「传」分开：看的是内容，传的是引用。由 Skill 参数约定与系统提示共同约束。

场景二 · Mask 后不可见

Policy 注入掩码，模型全程不接触真值

模型不需要理解的值（文件 URI、对象 ID 这类指针字段），送模之前就被替换成引用占位符。 替换规则由两层 Policy 注入：通用 Policy 按字段名兜底（fileUri、fileId、*Url…）， 业务 Policy 按工具粒度增删覆盖，业务优先。

真值：fileUri = "https://…/very/long/path?token=…"
送模后：fileUri = ${a1b2c3d4.fileUri} ← 模型所见即所填

模型只是照抄占位符，真值从入库到执行始终留在 Runtime 侧。

04

真值与保障

真值从哪来、怎么变

只从工作记忆取：先查全量结果集，未命中再查工具适配视图。resultId 由 Runtime 统一生成， 对内保留与 toolCallId 的映射，可追踪、可对账。

上下游结构不一致时按参数策略转换：[563,728] 自动变成 [{"file_id":"563"},…]，模型和工具都不用动。

出错怎么办

引用非法、结果不存在、字段没有、转换失败，一律短路：${…} 原文绝不透传给工具， 错误明确回给模型，引导改写后重试。

结果带会话作用域和有效期，过期或越权即拒绝；并行链路必须显式写 resultId，不允许含糊的「上一条」。

省 Token大结果不再回灌复述，输入与时延同降
抄不错真值不经模型之手，杜绝截断改写
结构解耦上下游 Schema 差异由策略转换消化
零改动能力在框架层，存量工具无感接入

模型决定引用哪条结果的哪个字段，Runtime 保证真实、适配、合法，然后才执行。
