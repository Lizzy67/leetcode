# 工具结果引用机制 · 开发接入规范

> 状态：V1 草案（供工具接入方与运行时开发评审）  
> 配套阅读：`docs/工具参数引用/tool-param-ref-mechanism.md`（顶层设计）、`docs/工具参数引用/tool-param-ref-example.html`（端到端示例）、`docs/工作记忆引用/workmemory-ref-scheme.md`（早期方案）  
> 规范用语：**必须** / **禁止** 为强制项，**建议** 为推荐项，**可选** 为按需项。

---

## 1. 目的与读者

本规范定义工具返回结果在智能体运行时中的**存储、送模呈现与引用回填**规则，供以下角色使用：

| 角色 | 关注章节 |
|------|----------|
| 工具 / 业务接入方 | §2 适用场景、§4 呈现分类、§5 选型指引、§6 接入步骤、§7 策略配置、§11 产出角色、§12 应用变量名 |
| 运行时（Runtime）开发 | §3 核心概念、§8 运行时行为、§9 失败与歧义、§11 多轮误选防护、§12 语义词典 |
| 测试 | §10 验收清单、§11.6、§12.6 |

一句话总述：**两类引用走同一执行前拦截器。** 工具结果引用：返回默认入工作记忆并分配短结果标识（resultId），按呈现策略以原文、掩码占位或完全隐藏面向模型，下游入参写 `${resultId.path}`。应用变量名：包名等稳定标识由模型写 `${namespace.实体.属性}`，运行时查语义词典回填；词典命中时业务工具一次调用完成，查询已安装应用只出现在未命中或歧义的兜底路径。两类解析失败都短路，不把 `${…}` 原文传给工具。

## 2. 适用场景

### 2.1 应当接入（命中任一即建议接入）

| 编号 | 场景 | 典型特征 |
|------|------|----------|
| S1 | 跨工具结果传递 | 上游返回 URI / ID / 大段文本，下游以同值为入参（先搜图再拼图再发布） |
| S2 | 指针型字段 | `fileUri`、`objectId`、ID 列表等：模型无需理解内容，只需转交 |
| S3 | 长值防抄错 | 值超过约 64 字符或含随机串（token、签名 URL），模型照抄易截断/改写 |
| S4 | 大结果省 Token | 返回体大，模型只需读摘要，不需读全量 |
| S5 | 结构不一致 | 上游输出结构 ≠ 下游入参结构，需执行前变换（配合 beforeHookPolicy） |
| S6 | 敏感 / 不宜送模字段 | 内部标识、调试信息、隐私字段，不希望进入模型上下文 |
| S7 | 应用变量名，省掉查已安装应用 | 权限、跳转等工具要真实包名，用户只说「抖音」「微信」。详见 §12 |

### 2.2 不适用（不要为这些场景引入引用）

- 用户原话中的短字面量（相册名、数量、城市名）：模型**直接填写**；
- 单工具调用、无下游消费的结果字段；
- 模型需要**改写加工**后再输出给用户的内容（引用只做原值转交，不做改写）。

应用展示名本身是短字面量，但写入 `bundleName` / `packageName` 时**必须**走 §12 的应用变量名，不把展示名或凭记忆编造的包名直接填进该参数。

## 3. 核心概念

### 3.1 存储结构（工作记忆，会话作用域）

| 结构 | 内容 | 是否可进模型上下文 |
|------|------|--------------------|
| `resultDataList` | 工具返回的**业务主体**，引用解析的**主数据源**（优先查） | 是——具体以原文还是掩码形态呈现，由呈现策略决定 |
| `dataForTool` | 仅供运行时 / 执行层消费的**附加数据**（端侧打开用长 URI、内部句柄等），引用解析的次级数据源 | **否——任何形态都不进上下文** |
| `resultId ↔ toolCallId` 映射 | 对模短标识 ↔ 对内调用标识 | resultId 可见，toolCallId 不送模 |

- `resultId` **必须**由运行时统一生成（推荐 `hex8(hash(toolCallId))`），全链路唯一算法，**禁止**各子系统自行派生。
- 每条结果**必须**记录作用域（会话 / 租户 / 设备）与有效期（TTL）。

### 3.2 引用语法

```
${resultId.path}
```

结果引用：

- 首段为 `resultId` 或对模别名（§11.2），字符集 `[A-Za-z][A-Za-z0-9_]*`，不含 `.`；首个 `.` 之后为字段路径（受限 jsonpath，禁函数、禁越界表达式）。

应用变量名（语义实体引用，§12）：

```
${namespace.实体.属性}
```

- 示例：`${app.抖音.bundleName}`、`${app.douyin.bundleName}`。
- `namespace` 为已注册命名空间，如 `app`、`contact`、`device`，以及 §11.5 的保留命名空间 `role`。

判别顺序：**首段命中已注册命名空间 → 语义实体 / 角色引用；否则按结果引用解析。** 占位符必须作为完整参数值或值内完整片段出现，模型禁止改写其内部字符。

## 4. 送模呈现分类（规范核心）

工具返回中的每个字段，经呈现策略（`capturePolicy`）判定后，归入以下三类之一。

> 术语对照：早期文档中的 `maskPolicy` 即本规范 `capturePolicy` 的掩码子集；本规范统一用 `capturePolicy` 表述三类呈现的完整判定。

### A 类 · 可见呈现（VISIBLE）

| 项 | 规则 |
|----|------|
| 存储 | `resultDataList` |
| 送模形态 | **原文**进入模型上下文 |
| 下游传参 | 模型**仍必须输出引用**（看传分离）：读过 ≠ 可以抄 |
| 适用 | 模型必须阅读其内容才能推理、播报或决策的字段：`summary`、`aiDesc`、状态结论 |

> A 类是「看」与「传」分离的场景：值对模型可见，供其理解；但写入下游工具入参时仍写 `${rN.path}`，由运行时回填，杜绝长文抄写错误。

### B 类 · 掩码呈现（MASKED）

| 项 | 规则 |
|----|------|
| 存储 | `resultDataList`（真值只在工作记忆） |
| 送模形态 | 字段**出现**在上下文中，但值被替换为引用占位符本身（如 `"collageUri": "${r2.collageUri}"`） |
| 下游传参 | 模型照抄所见占位符（所见即所填） |
| 适用 | 模型需要**感知存在并决定传给谁**、但无需读内容的指针型字段：`fileUri`、`*Url`、ID 列表 |

> B 类让模型知道「有一个可引用的对象」，并把引用形态直接放在它眼前；模型的唯一正确动作是原样回传。

### C 类 · 隐藏（HIDDEN）

| 项 | 规则 |
|----|------|
| 存储 | `dataForTool` |
| 送模形态 | **完全不出现**在上下文中（连字段名和占位符都没有） |
| 下游传参 | 不经模型：由运行时 / 执行层按约定直接衔接；或由 Skill 文档化的固定路径引用 |
| 适用 | 模型全程无需感知的执行层数据：端侧打开用的内部 URI、调试信息、协议附加字段 |

> C 类与 B 类的分界：**模型是否需要参与「把它传给谁」的决策**。需要 → B（给占位符让它转交）；不需要 → C（运行时自动衔接，模型连存在都不知道）。

### 分类速查

| | A 可见 | B 掩码 | C 隐藏 |
|---|---|---|---|
| 进上下文 | 原文 | 占位符 | 否 |
| 存储位置 | resultDataList | resultDataList | dataForTool |
| 模型动作 | 读内容 + 传参写引用 | 照抄占位符 | 无感知 |
| 引用可解析 | 是 | 是 | 是（次级查找） |

## 5. 选型指引

对返回结构中的每个字段依次回答：

```
① 模型需要阅读该值的内容（推理/播报/决策）吗？
      是 → A 类（可见呈现；下游传参仍须引用）
      否 ↓
② 模型需要决定「这个值传给哪个下游工具」吗？
      是 → B 类（掩码呈现，占位符所见即所填）
      否 ↓
③ 仅运行时 / 执行层消费 → C 类（隐藏，入 dataForTool）
```

叠加规则：

- 命中 §2.1 S3（长值）且回答①为「是」：仍归 A 类，但**建议**同时产出短摘要字段供播报，长原文按需折叠；
- 命中 S6（敏感）：无论①②如何，**必须**至少 B 类；模型完全无需感知时**必须** C 类；
- 列表字段（如 `merged_id_list`）：默认 B 类；若下游入参结构不一致，叠加参数转换规则（§7.3）。

## 6. 工具接入步骤

接入方按以下顺序完成，全程**不修改工具实现与参数签名**：

1. **字段分类**：按 §5 对返回结构逐字段标注 A / B / C。入参若是包名等稳定业务标识，改走 §12，不按 A / B / C 分类；
2. **配置 capturePolicy**：仅需声明与通用规则不同的例外（见 §7.2）；C 类字段若由工具直接产出，写入返回体的 `dataForTool` 区段；
3. **配置参数转换规则**（可选）：下游入参结构不一致时，为目标参数编写 JSONata 表达式（见 §7.3）;
4. **Schema 核对**：指针型入参声明 `accept`（产出角色 + 值类型，见 §11.3）；描述中给出引用写法，由运行时按当次工作记忆填入合法枚举；
5. **Skill 约定**：确认所属技能已包含通用引用规则（引用照抄、可见仍引用、禁止编造真值）。`bundleName` 类参数约定填写 `${app.<应用名>.bundleName}`（§12.5）；
6. **按 §10 清单自测**。

## 7. 策略配置规范

策略仓三层结构，细粒度覆盖粗粒度：**参数级 > 工具级 > 通用**。

### 7.1 通用规则（全局兜底）

```json5
global.capturePolicy {
  mask: ["*Uri", "*Url", "*_id_list", "fileId", "objectId"]   // 命中字段名模式 → B 类
  // 未命中任何规则的字段默认 A 类（可见）
}
```

### 7.2 工具级规则（业务例外，覆盖通用）

```json5
searchPhotos.capturePolicy {
  visible: ["summary"]        // 显式 A 类（即使命中通用 mask 模式也放行）
}
createCollage.capturePolicy {
  visible: ["aiDesc"],
  hidden:  ["debugTrace"]     // 显式 C 类：剥离至 dataForTool，不进上下文
}
```

- 同一字段命中多条时按**最严格**生效：`hidden > mask > visible`；
- C 类字段的两个来源等价：工具返回体自带 `dataForTool` 区段，或 `capturePolicy.hidden` 由运行时从主体剥离。

### 7.3 参数转换规则（参数级，执行前变换）

引用求值**之后**、schema 校验与工具执行**之前**，按 JSONata 表达式变换（详见 `docs/工具参数引用/tool-param-ref-mechanism.md` §场景 S6）：

```json5
createCollage.beforeHookPolicy {
  images: "$map($, function($v) {{ 'file_id': $string($v) }})"   // $ = 引用展开后的真值
}
```

约束：表达式**必须**来自策略配置（**禁止**模型生成）；禁用 `$eval`；求值超时与输出上限由运行时统一设定；失败走短路。

## 8. 运行时行为（规范性）

1. **写入**：工具成功返回 → 业务主体写 `resultDataList`，附加数据写 `dataForTool`，分配 `resultId` 并登记作用域与 TTL；
2. **送模**：按 capturePolicy 渲染送模视图（A 原文 / B 占位符 / C 剥离）；B 类占位符使用对模别名（§11.2），形态与引用语法一致（所见即所填）。每一轮推理前，在上下文尾部注入由工作记忆重算的引用清单（§11.3）；
3. **解析**：拦截器在**所有**工具 invoke 前递归扫描参数，对每个 `${…}` 按 §3.2 判别。语义实体引用查语义词典（§12），不查工作记忆。结果引用先把别名还原为内部 `resultId`，再查 `resultDataList`，未命中查 `dataForTool`；校验作用域、有效期，以及参数 `accept` 的角色与值类型（§11.4）；
4. **变换与校验**：角色与值类型通过后，命中参数转换规则才执行表达式；最终参数过 schema 校验；
5. **调用**：全部必要引用完成求值且参数合法，才向工具发出请求。

## 9. 失败与歧义处理

| 情形 | 行为 |
|------|------|
| 引用语法非法 / resultId 不存在 / 路径无效 | **短路**：不调用工具，返回结构化错误（错误类型 + 位置），**禁止**把 `${…}` 原文透传给工具 |
| 别名存在，但路径不存在，或展开值无法满足参数的值类型（例如需要 uri，取到的是状态对象或另一类标识） | **短路**，错误类型 `REF_TYPE_MISMATCH`。正文写明该别名所属工具与产出角色，并列出本参数当前合法引用（别名 + 人读标签）。**禁止**运行时改绑到其他结果 |
| 引用过期 / 作用域不匹配 | 同上，错误注明过期或越权，引导模型重新获取 |
| 转换失败 / 校验不过 | 同上，**禁止**透传未变换或半成品参数 |
| 解析出多个候选 | **禁止静默选一**：返回候选摘要（引用 + 人读标签，不含真值），或将合法引用动态写入该参数的 schema 枚举供模型 / 用户选择 |
| 图片等非引用形态裸值出现在引用约定参数位 | 短路拒绝（防编造 URI） |
| 应用变量名未收录 | **短路**，错误类型 `ENTITY_NOT_FOUND`。不调用业务工具。按该命名空间的兜底策略进入「查询已安装应用」，查询结果校验后刷新词典（§12.4） |
| 应用变量名命中多条 | **短路**，错误类型 `ENTITY_AMBIGUOUS`。返回候选摘要（展示名 + 消歧引用，不含包名真值），或把合法引用写入该参数枚举。**禁止**按安装顺序或最近使用静默选一个包 |

## 10. 测试验收清单

- [ ] A 类字段：原文可见；下游传参为引用而非抄写原文；
- [ ] B 类字段：上下文中为占位符；模型回传占位符后工具收到真值；
- [ ] C 类字段：上下文中无该字段；执行层正常取得数据；
- [ ] 引用指向不存在的 resultId / 路径：工具未被调用，错误结构化返回；
- [ ] 引用过期（跨会话 / 超 TTL）：短路且提示过期；
- [ ] 参数转换：列表→对象数组正确；**单元素输入**输出仍为数组；空列表行为符合预期；
- [ ] 多候选歧义：未静默选取，候选摘要或枚举生效；
- [ ] 存量工具未配置任何策略：通用规则兜底生效，调用链路无回归。
- [ ] §11.6 多轮误选用例全部通过。
- [ ] §12.6 应用变量名用例全部通过。

## 11. 多轮误选 resultId 的防护

### 11.1 现象与原因

线上失败形态：下游参数需要搜图结果里的图片 URI，模型却填了**时间上更近的另一次工具调用**的 `resultId`。路径对不上，或展开后的值不是 URI，执行前转换失败。

原因在送模方式，不在转换器：

| 原因 | 表现 |
|------|------|
| 内部 `resultId` 是 8 位 hex，不含工具名 | 多轮之后 `${a1b2c3d4.fileUri}` 与 `${e5f6a7b8.fileUri}` 对模型无差别 |
| 近因 | 早轮搜图结果被后续对话挤出注意力，或被历史压缩写成「已搜到照片」；上下文里仍完整保留的占位符来自最近一次工具 |
| 同形占位符 | 掩码后多个工具都呈现为 `${….uri}`，模型按形状抄最近的一条 |
| 约束停在提示词 | Skill 只要求「填 `${resultId.path}`」，没有把**哪一条结果**绑到**哪一个参数** |

提示词里写「请使用搜图工具的 resultId」不能作为修复手段。多轮后软约束竞争不过近因。下面四条按落地顺序执行，前三条为**必须**，第四条为**可选**。

### 11.2 对模别名（送模层）

内部 `resultId`（`hex8(hash(toolCallId))`）继续作为存储键。送给模型的标识改为会话内稳定别名：

```text
alias = {toolName}_{ordinal}
示例：searchPhotos_1 、createCollage_1
```

- `toolName` 只保留字母与数字；`ordinal` 为该工具在本会话内的序号，从 1 递增。
- B 类占位符、A 类字段旁的引用提示，一律使用别名：`${searchPhotos_1.fileUri}`。
- 解析顺序：别名表 → 内部 `resultId` → 字段路径。模型若仍输出历史中的 hex，运行时照常解析，送模不再展示 hex。
- 别名写在占位符内部。模型照抄时自带工具名，最近一次拼图结果是 `createCollage_1`，不会被当成搜图结果。

### 11.3 引用清单（上下文层）

每一轮模型推理前，运行时**从工作记忆重算**一份引用清单，放在上下文尾部（当前用户目标之后）：

```text
可引用结果（以本清单为准）：
- searchPhotos_1  [photoSet]  18张  海边日落   ${searchPhotos_1.fileUri}
- createCollage_1 [collage]   已生成拼图     ${createCollage_1.collageUri}
```

规则：

- 数据源是工作记忆，不从对话原文抽取。历史压缩时用重算结果**整段替换**清单，摘要模型不得改写清单。
- 每条包含：别名、产出角色、人读标签（取 `summary` 等 A 类字段，超长截断）、可引用占位符、产生轮次。
- 每个产出角色默认保留最近 3 条仍有效结果；更早的条目可解析，默认不进清单。参数枚举需要时再展开。
- 清单使正确标识出现在决策点附近。近因作用在清单上，不再作用在「最近一条工具原文」上。

### 11.4 产出角色与动态枚举（参数层，根治）

工具声明自己产出的角色；消费参数声明自己接受的角色和值类型。

```json5
searchPhotos.produces {
  role: "photoSet",
  labelFrom: "summary",
  fields: {
    fileUri:        { valueType: "uri" },
    merged_id_list: { valueType: "idList" }
  }
}

publishNote.params.images.accept {
  roles: ["photoSet"],
  valueTypes: ["uri", "idList"]
}
```

运行时在**本次**把该工具 schema 交给模型之前，用工作记忆过滤：

| 命中条数 | 行为 |
|----------|------|
| 0 | 参数描述写明当前无合法引用，需先调用产出该角色的工具。该参数拒绝非引用字面量 |
| 1 | 描述中给出唯一占位符，例如「填写 `${searchPhotos_1.fileUri}`」 |
| 多条 | `enum` 只含这些占位符，每项附人读标签。角色不符的结果（如 `createCollage_1`）不进入枚举 |

拦截器在转换之前执行两道校验，任一失败即短路，不进入 JSONata：

1. 引用的结果角色 ∈ 参数 `accept.roles`（未配置 `accept` 的存量参数跳过此条）；
2. 目标字段的 `valueType` ∈ 参数 `accept.valueTypes`，且路径存在。

因此「就近抄了别的工具」在转换阶段之前就被拒绝，错误里带上搜图那条合法引用，下一轮模型从错误文本照抄即可。

同一角色有多条时（两次搜图），**禁止**按时间静默选取。返回候选摘要或枚举。只有参数显式配置 `onMultiple: latest` 时，才允许绑定该角色最近一条；该策略是配置项，类型不匹配时运行时仍然不得改绑。

### 11.5 角色引用（可选）

当参数接受的角色在当前工作记忆中**恰好一条**有效结果时，允许模型写保留命名空间引用，由运行时展开：

```text
${role.photoSet.fileUri}
```

判别与现有语义引用相同：首段为已注册命名空间 `role`。求值按角色 + 字段过滤工作记忆：0 条失败，1 条成功，多条按 §11.4 返回别名候选。多条时不得展开为时间上最近的一条。

模型在唯一命中时不再选择 `resultId`。这是「搜图只有一次、后面又调用了很多别的工具」时的直接写法。

### 11.6 验收补充

- [ ] 搜图之后连续插入 8 轮无关工具调用，下游图片参数仍解析到 `searchPhotos_1` 的 URI；
- [ ] 送模占位符含工具名别名，不含裸 hex（历史 hex 引用仍可解析）；
- [ ] 历史压缩后，清单仍列出搜图结果，且与工作记忆一致；
- [ ] 下游参数 `accept.roles = [photoSet]` 时，填入 `createCollage_1` 被短路，错误中含 `${searchPhotos_1.fileUri}` 与摘要标签，工具未被调用；
- [ ] 两次搜图并存时，枚举含两条且带各自摘要；运行时未自动取最近一条；
- [ ] `${role.photoSet.fileUri}` 在唯一 photoSet 时展开为该次搜图 URI；两条 photoSet 时短路并给出两条别名。

落地顺序建议：先做 §9 的 `REF_TYPE_MISMATCH` 回带合法引用（立刻改善重试），再做别名与清单，最后做 `accept` 动态枚举；角色引用在枚举稳定后打开。

## 12. 应用变量名：省掉查询已安装应用

### 12.1 场景

权限、跳转、卸载等工具的入参是包名（`bundleName` / `packageName` / `bundleId`）。包名语义弱，用户只说「抖音」「微信」。

原路径固定两轮：

```text
用户：关掉抖音的通知
  ① 模型调用 getAllInstalledApps
  ② 模型从列表抄出包名，再调用 forbidPermission
```

模型若跳过第 ① 步、凭记忆填写包名，会把编造值送进业务工具。应用类工具数量多，不逐个改参数签名。

### 12.2 变量方案分类

这一类与 §4 的三种送模呈现不是同一条数据通路。§4 描述**本会话工具结果**怎么进上下文；应用变量名描述**稳定业务标识**怎么从词典回填。

| | 结果引用（§4） | 应用变量名（本节） |
|---|---|---|
| 真值来源 | 工作记忆 `resultDataList` / `dataForTool` | 语义词典（同义词表 + 实体属性映射表） |
| 模型写入 | `${searchPhotos_1.fileUri}` | `${app.抖音.bundleName}` |
| 真值是否进上下文 | 由 A / B / C 决定 | **不进**。模型不读包名，只写变量名 |
| 热路径 | 上游工具已经调用过，下游只回填 | 词典命中时**一次**业务调用完成 |
| 省掉的一轮 | 为抄写长值而多出的整理 | **查询已安装应用** |

联系人 ID、设备 ID 用同一语法，命名空间改为 `contact`、`device`。下面用 `app` 写死规则，其他命名空间照此注册。

### 12.3 写法与求值

模型在包名参数中填写：

```text
${app.抖音.bundleName}
${app.douyin.bundleName}
```

`app` 是命名空间，中间段是用户说的应用名或别名，最后一段是属性名。运行时在业务工具执行前求值，工具仍声明 `bundleName: string`，收到的是包名真值。

两张表：

| 表 | 作用 | 示例 |
|----|------|------|
| T1 同义词 | 俗称、英文名、大小写归一成规范实体 | `douyin` / `抖音` → `抖音`。需区分安装包时不要并成同一实体 |
| T2 实体属性 | 按命名空间、规范实体、属性取真值 | `app` + `抖音` + `bundleName` → 该设备上的包名 |

求值顺序：

1. 解析出 `namespace`、`entityRaw`、`attribute`；
2. `entity = T1.normalize(entityRaw)`；
3. 用当前设备上下文查 T2。映射行可以带平台维度：操作系统、厂商定制系统、设备类型、区域、版本。未填写的维度视为通配。设备上下文来自本轮会话，不由模型填写；
4. 1 条 → 回填并调用业务工具；0 条 → `ENTITY_NOT_FOUND`；多条 → `ENTITY_AMBIGUOUS`。

命中时的调用：

```text
模型:    forbidPermission({ "bundleName": "${app.抖音.bundleName}" })
运行时:  T1 归一 → T2 命中
工具:    forbidPermission({ "bundleName": "<词典中的包名>" })
```

会话里不出现 `getAllInstalledApps`。

T2 的数据来源可以并用：预置常见应用、设备侧已安装列表懒加载刷新、用户纠正写回。词典按作用域存放（设备 / 租户 / 会话），会话级覆盖设备级。

声明了语义引用的参数，裸包名和裸展示名都拒绝，错误类型 `REF_LITERAL_FORBIDDEN`，提示改为 `${app.<应用名>.bundleName}`。

```json5
forbidPermission.params.bundleName {
  refKind: "semantic",
  namespace: "app",
  attribute: "bundleName"
}
```

### 12.4 未命中与歧义：查询才出现

热路径是一轮。只有词典没有这条，或同一应用名对上多个包时，才进入第二轮。业务工具在这一轮不会被调用，`${…}` 也不会原样传进去。

```text
forbidPermission(bundleName=${app.某冷门应用.bundleName})
        │
        ├─ T2 命中 1 条 → 回填，本轮结束
        │
        ├─ 0 条 → ENTITY_NOT_FOUND
        │         按命名空间兜底策略调用 getAllInstalledApps
        │         校验后刷新会话级或设备级 T2
        │         模型用同一个应用变量名重试业务工具
        │
        └─ 多条 → ENTITY_AMBIGUOUS
                  返回候选摘要，或把消歧后的变量名写入参数枚举
                  模型改写实体名后重试，例如 ${app.抖音国际版.bundleName}
```

兜底查询的结果可以同时写入工作记忆。模型下一轮仍写应用变量名，不从查询列表抄包名。刷新词典之后，同一个 `${app.抖音.bundleName}` 即可命中。

多条候选时禁止按安装顺序、最近使用或列表第一条静默选择。

### 12.5 Skill 约定

对包名参数只保留短规则：

- 填写 `${app.<用户所说的应用名>.bundleName}`；
- 禁止凭记忆编写 `com.` 开头的包名；
- 运行时返回未收录或歧义之前，不先调用 `getAllInstalledApps`。

约束优先级与结果引用相同：拦截器求值 > 参数 `refKind` > Skill > 系统提示。

### 12.6 验收

- [ ] 词典已有「抖音」：`forbidPermission` 收到包名真值；本会话未调用 `getAllInstalledApps`；上下文中不出现包名真值；
- [ ] `${app.douyin.bundleName}` 与 `${app.抖音.bundleName}` 求值到同一条 T2 记录（在 T1 已归一的前提下）；
- [ ] 未收录应用：业务工具未被调用，错误类型为 `ENTITY_NOT_FOUND`；兜底查询并刷新词典后，同一变量名的下一次业务调用命中；
- [ ] 同一应用名对应两个包：错误类型为 `ENTITY_AMBIGUOUS`，候选不含包名真值，运行时未自动选包；
- [ ] 参数 `refKind = semantic` 时，裸包名被拒绝，工具未被调用；
- [ ] 同一应用名在不同操作系统下取到该平台的标识；两个维度同时匹配时走歧义，不静默合并。
