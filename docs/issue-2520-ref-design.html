TaiChu Issue #2520 · Design Alignment

跨端 Reference Bundle：PC 导出 → Relay 透传 → 手机侧本地化

将 #2520 V0 设计、Review concern、持久化增强评论，与 Lizzy67 定稿的 8 条决策对齐为可执行简报。 详细一页纸见 docs/workmemory-ref-onepager.html。

相对旧一页纸的关键变更

  • resultId：统一 UUID.randomUUID().toString().substring(0, 8)（取 UUID 字符串前 8 位）。
  • 可见/不可见：不可见=进模前加 mask；可见=原样进模，输出仍只出引用，Runtime 还原。
  • 逻辑架构：① policy(+正则) mask 并缓存 resultDataList → ② Skill/Prompt 约束出引用 → ③ Runtime 解析真值。
  • 入参：递归遍历 JSON，整体引用 + 值内引用。
  • SubAgent：出入 mask 均不还原；裁 memoryList 交回。

V0 五阶段（部署视角）

1. 捕获PC 注入 CapturePolicy；Runtime 选字段写 Store / extendData
2. PC 内流转模型见 8 位 resultId ref；执行副本还原真值
3. 跨端导出summary 保留完整 ref；按需打 referenceBundle
4. Source 本地化service 校验导入并 remap 为本地 8 位 ref
5. 最终消费主 Agent 交 sink；execution-only resolve

SubAgent 注

输入 mask 不还原，输出 mask 也不还原；需要裁剪 memoryList{引用变量名:变量值} 返回父会话。

协议要点速查

CapturePolicy（PC → Runtime）

  • 不可变快照；非法配置创建 fail fast。
  • 精确 tool key + JSON Pointer；已有非空 dataForTool 时原生契约优先。

referenceBundle（PC → service）

  • terminal private 字段 / extendData；不改 Relay 公共协议。
  • items.sourceReference 集合 = summary 唯一完整 ref 集合。
  • payload = Base64(JSON value)；校验 size / sha256 / kind。

融合回复指代

  • 合法：下面是脑图 ${uuid.fileLink} 中的完整 token 由交付层保留。
  • 禁止把 ref 截断、插值进 URL、或把内部 ref 直接给用户。

resultId 生成

  • UUID.randomUUID().toString().substring(0, 8)
  • toolCallId：仅追踪，不进公开引用身份

仍需完成（来自 #2520 §4.2）

  1. PC：真实工具名单、规范化结果样本、生产 CapturePolicy 与开关。
  2. Runtime：SubAgent summary 完整 ref 通用保留规则；UUID 身份落地；Message.extendData 持久化增量。
  3. taichu-service：release 分支 consumer + 真实 sink E2E。
  4. 联合 smoke：PC 权威值 / bundle / source Store / sink 参数 SHA-256 一致。
  5. 负向：缺项/多项/digest 错误/跨 session → 全部 fail closed，禁止降级长文本搬运。

验收标准

  • 两端模型上下文均不出现完整长 URL / 载荷；用户结果不泄漏内部 ref。
  • bundle 只含 summary 实际使用项；Relay 保持 opaque 透传。
  • 不可见引用可随 Session 历史恢复；可见引用会话结束即消失。
  • 用户最终能下载文件或看到脑图。
