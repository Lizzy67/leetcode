## 二、关键术语

**工具 / 工具调用：** 由大模型触发、由运行时执行的外部能力调用；模型通常输出工具名称及参数。

**工具入参 / 业务参数：** 工具执行所需且与具体业务相关的参数，例如应用包名、文件地址等；区别于由运行时注入的用户身份、会话标识等系统参数。

**引用占位符：** 模型在工具入参中填写的、用于表达引用意图而非直接给出业务真值的字符串；通常具有统一边界形态，且作为完整参数值出现。

**结果引用：** 引用本会话中某次工具返回结果内某一字段的引用方式。

**结果标识：** 分配给某次工具返回结果、供模型侧进行结果引用的短标识。

**字段路径：** 在工具返回的结构化结果中定位目标字段的路径表达。

**语义实体引用：** 以命名空间、实体、属性三段表达“哪个对象的哪个属性”的引用方式。

**命名空间：** 语义实体所属的类别域，例如应用、联系人、设备等，可扩展。

**工作记忆：** 按会话或等价作用域缓存工具返回结果，并支持按结果标识及字段路径检索的存储组件。

**语义词典：** 用于语义实体求值的数据组件，至少包括同义词或别名归一关系，以及实体属性到真实业务标识的映射关系。

**同义词 / 别名归一：** 将实体的不同写法映射为同一规范实体名的处理过程。

**实体属性映射：** 根据命名空间、规范实体名及属性名查询得到真实业务标识的处理过程。

**引用解析拦截器：** 位于工具真正执行之前，负责扫描工具参数中的引用占位符，并完成求值回填或短路处理的框架组件。

**回填：** 将引用占位符替换为查表或检索得到的真实参数值的过程。

**短路：** 在引用解析失败或出现歧义时，不将未展开的引用占位符传递给工具，并中止本次工具执行或转入错误处理 / 兜底处理的过程。

**透传：** 未经求值即将引用占位符原文直接传递给工具的行为；本发明予以禁止。

**送模掩码：** 在将工具结果提供给大模型之前，对选定字段以引用占位符替代真实值进行展示的处理。

**所见即所填：** 模型上下文中展示的引用占位符形态，与其随后写入工具入参的形态保持一致，以便原样回传。

**热路径：** 引用求值命中、无需额外查询类工具即可完成业务工具调用的主路径。

**兜底路径：** 引用求值未命中或出现歧义后，通过查询类工具获取信息、必要时刷新词典并再次发起业务调用的恢复路径。

**工具零改动：** 不修改存量工具的参数签名与实现逻辑，仅通过框架层引用解析能力使同类工具自动获得引用填参支持。

**系统注入参数：** 例如用户身份标识、会话标识等，通常由运行时根据鉴权与会话上下文注入、不由模型填写的参数；与本发明所述业务参数引用相区别。

**看传分离：** 模型为完成推理可以阅读字段真值或摘要，但在向下游工具传递该字段时仍使用引用占位符，由框架回填真值。

## 三、侵权取证方式

### 3.1 取证原则

1. 取证对象为被控侵权产品或服务对外可观测的行为与表现，而非依赖获取其内部非公开设计文档或源代码。  
2. 取证内容应尽量与本发明创新点逐项对应；仅凭响应变快、对话轮次减少、回答更准确等效果表象，不足以单独证明采用了本发明技术方案。  
3. 取证过程应固定对话话术、操作步骤、时间戳、设备与网络环境、原始日志或抓包文件，形成可复核的证据链。

### 3.2 主要取证方法

**（1）双态对比取证**  
在可观测通道中，对比模型侧或对话协议中记录的工具调用参数，与实际到达业务系统、设备接口或应用侧的请求参数。若前者呈现引用占位符或短引用形态，后者呈现真实包名、真实 URI 等业务真值，则可证明存在“模型输出引用意图、执行前完成求值回填”的处理。

**（2）多工具一致性取证**  
针对多个参数类型相似但业务不同的工具重复进行双态对比。若均表现出相同的“引用态入参 → 执行侧真值”行为模式，可证明该处理位于统一调度或统一网关层，而非单一工具内部定制实现。

**（3）语义别名归一取证**  
在相同设备与会话条件下，分别使用同一应用的不同别名或中英文名称发起相同业务意图。若最终落到同一真实应用标识，且对预置或热门应用常常无需先调用“查询全部已安装应用”类工具，可证明存在别名归一与实体属性映射机制，并支持热路径一次业务调用。

**（4）结果引用与掩码取证**  
构造“上一工具产生长标识或文件地址，下一工具消费该字段”的任务链。若模型可见上下文中该字段以短引用或占位符形式出现，而下游实际请求携带与上一工具返回一致的完整真值，可证明存在工作记忆类结果引用，以及可选的送模掩码与所见即所填机制。

**（5）失败短路与禁止透传取证**  
故意输入不存在的实体名、非法引用形态或不存在的结果标识。若业务工具侧未收到含引用边界字符的非法包名或非法地址，且产品返回引用无法解析、未找到映射、存在多个候选等明确错误或引导，可证明存在解析失败短路且禁止占位符透传的机制。

**（6）歧义与多候选取证**  
在存在多个候选真实标识的环境中发起语义引用类操作。若系统提示选择、返回候选列表或报错，而非静默绑定其中一个标识，可证明存在歧义处理策略。

**（7）兜底路径取证**  
对冷门或未预置映射的实体发起业务请求。若首次出现查询类工具调用或映射补充过程，并在之后同类请求可转为一次业务调用成功，可证明存在查询兜底及词典刷新机制。

**（8）公开材料旁证**  
收集被控产品的帮助文档、技能说明、错误提示文案、演示视频、发布材料中关于“使用引用填写参数”“禁止编造包名”“应用映射 / 已安装应用同步”等表述，作为辅助证据，并与上述行为取证相互印证。

### 3.3 常用取证通道

可依法或依产品开放能力取得的通道包括但不限于：官方开放接口与调试日志、客户端开发者选项或调试桥、网络代理抓包、企业版审计日志、错误回执与提示文案、自动化脚本驱动的对话复现环境等。

### 3.4 创新点与取证方法对应关系

| 技术创新点 | 推荐取证方法 |
|------------|--------------|
| 工具执行前统一引用解析与回填 | 双态对比取证；时序上真值出现于工具成功执行之前 |
| 结果引用与语义实体引用双协议 | 分别复现跨工具传 URI 场景与包名语义引用场景 |
| 同义词归一 + 实体属性映射 | 语义别名归一取证；热路径少查询取证 |
| 解析失败短路、禁止透传 | 失败短路与禁止透传取证 |
| 框架层生效、工具零改动覆盖 | 多工具一致性取证 |
| 送模掩码 / 所见即所填 | 结果引用与掩码取证 |
| 查询兜底与词典刷新 | 兜底路径取证 |
| 歧义不静默选一 | 歧义与多候选取证 |

### 3.5 取证结论形成方式

对同一被控产品，宜采用“公开材料线索 → 标准话术复现 → 双态或端侧行为坐实 → 多工具与多别名交叉验证 → 失败与歧义用例补强”的顺序形成完整证据链，从而证明其技术方案落入本发明创新点所对应的技术特征组合。
