AGENT · TOOL CALLING · EXAMPLE

端到端样例：搜图 → 拼图 → 发布

用户一句「把上周的滑雪照片拼成一张长图，发到我的相册笔记」，三个工具串联完成。 全程模型只写引用：ID 列表和长 URI 被 mask、从未见过真值；长文案可见、供推理，但传参仍是引用。

01

三步执行

字段标记：可见模型能读到内容　mask送模前已换成引用，模型只见占位符
STEP 1 · 工具 searchPhotos

搜索照片，结果入库 r1

模型调用 searchPhotos(query="上周 滑雪")，返回结果写入工作记忆。
工具返回（Runtime 所见，入库 resultId = r1）
{
  "merged_id_list": [563, 728, 991],
  "coverUri": "https://photo.cloud/u9f3a…
    ?sig=eyJhbGciOiJI…（214 字符）",
  "summary": "找到3张滑雪照片，
    拍摄于1月18日雪场"
}
送模后（模型所见）
{
  "merged_id_list": "${r1.merged_id_list}"  ← mask·通用
  "coverUri": "${r1.coverUri}"          ← mask·通用
  "summary": "找到3张滑雪照片…"      ← 可见
}
模型据 summary 向用户播报「找到3张」；ID 和封面 URI 它不需要懂，只需拿得到。
STEP 2 · 工具 createCollage

引用 ID 列表拼图，结果入库 r2

模型出参（照抄所见占位符）
createCollage({
  "images": "${r1.merged_id_list}",
  "style": "long-strip"
})
Runtime beforeHook：先求值，再按 policy 转换
resolve → [563, 728, 991]
transform → [{"file_id":"563"},
  {"file_id":"728"}, {"file_id":"991"}]
工具返回（入库 r2）→ 送模后
{
  "collageUri": "${r2.collageUri}"      ← mask·业务
  "aiDesc": "三张照片自上而下：雪道
    全景、腾空瞬间、雪场合影，色调
    统一为冷蓝…（180 字）"        ← 可见
}
长 URI 被 mask；长文案保留可见，模型要读它来确认拼图效果、决定要不要直接用作笔记正文。
STEP 3 · 工具 publishNote

可见的用引用传，没见过的照抄

模型出参
publishNote({
  "fileUri": "${r2.collageUri}",   场景二：
    没见过真值，照抄占位符
  "content": "${r2.aiDesc}",     场景一：
    读过内容，传参仍写引用
  "title": "上周滑雪记录"        短字面量：
    模型自己写的，直接填值
})
Runtime 求值后实际调用
publishNote({
  "fileUri": "https://media.cloud/collage/
    7Qx2…?token=…（198 字符真值）",
  "content": "三张照片自上而下：…（180 字全文）",
  "title": "上周滑雪记录"
})
笔记发布成功，返回 noteId 再入库。整条链路模型没抄过一个长值，Token 只花在 summary 和 aiDesc 这两段真正需要读的内容上。
02

本例的 Policy 配置

mask 决定「模型看什么」，beforeHook 决定「工具收什么」

Mask Policy：通用兜底 + 业务覆盖

# 通用（所有工具生效，按字段名兜底）
global.maskPolicy {
  fields: ["*Uri", "*Url", "*_id_list", "fileId"]
}

# 业务（按工具覆盖，优先于通用）
searchPhotos.maskPolicy {
  keep_visible: ["summary"]     # 短摘要留给模型播报
}
createCollage.maskPolicy {
  keep_visible: ["aiDesc"]      # 长文案供推理，不 mask
}

coverUri、collageUri、merged_id_list 均命中通用规则被 mask；summary、aiDesc 由业务规则显式放行。

BeforeHook Policy：入参结构转换

# createCollage 执行前：images 参数
# 先 resolve 引用，再按表达式变换

# 伪代码（语义示意，$value = 展开后的真实列表）
createCollage.beforeHookPolicy {
  images: list(
    dict("file_id", string(item))
    for item in $value
  )
}

# JSONata（可执行等价，$ 即 $value）
createCollage.beforeHookPolicy {
  images: "$map($, function($v) {{ 'file_id': $string($v) }})"
}

# 若需叠加数量上限（至多前 18 项）：
#   $map($[[0..17]], function($v) {{ 'file_id': $string($v) }})

# publishNote 无需转换，
# beforeHook 只做引用求值与 Schema 校验

上为语义伪代码，下为可执行 JSONata（AWS Step Functions 同款选型）：逐元素转字符串再封装成对象，顺序保持，不足上限自动截短。表达式只能由工具接入方在 Policy 中书写，禁止模型生成；求值失败即短路。模型和两端工具都不感知这次转换。

ID 列表 / 长 URI　mask 后模型从未见过，占位符原样穿过三步
长文案 aiDesc　可见、可推理，但传参依然是 ${r2.aiDesc}
短字面量 title　模型自己生成的内容，照常直接填值
