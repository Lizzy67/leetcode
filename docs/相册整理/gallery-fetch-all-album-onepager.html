相册整理：全量搜索与接续追加

现状：搜索一次 500 张、相册一次 ≤500 张（已有 create / append），「把所有猫猫照片整理到萌宠相册」（2 万张）只能拿到第一页；也不支持接续说「再把狗狗的也整理进去」「把剩下的猫猫也整理进去」。方案：钉住两组原语，用「边搜边 append」的循环覆盖两个场景。

现状与边界

「所有猫猫照片整理到萌宠相册」
→
搜索 Skill500 / 次 · 出一张结果卡
→
r1 · 500 ids
→
创建相册 Skill一次 ≤500 张 · 已支持 create / append
→
相册 500 张，其余 19 500 丢失接续指令无法表达「排除已在相册的」

两组原语两个场景只差参数，编排规则写在 Skill 说明里

搜索 Skill

search({
  query:          "猫猫",
  mode:           browse | organize,   # organize = 不出卡 + 返回 cursor + filter(不在目标相册中) + ids mask
  cursor?:        ${r.nextCursor},      # 同一任务内续页
  target_album?:  "萌宠" | ${r.albumId}  # organize 的过滤目标：排除已在该相册内的照片（名或 id）
})
→ { ids(mask), nextCursor | null, total?, summary }

相册 Skill现有能力，基本不改

album({
  action:  create | append,             # 均为现有规格
  target:  "萌宠" | ${r.albumId},   # 模型传名或引用，工具侧解析成 id；同名多相册短路让用户选
  items:   ${r.ids}                  # 单次 ≤500，追加去重
})
→ { albumId, added, total_in_album }；流程结束出一张汇总卡

场景 1 · 一句话全量整理「把所有猫猫照片整理到萌宠相册」— 边搜边 append，靠 nextCursor 循环

第 1 轮
search(猫猫, mode=organize)
→
r1 · 500 ids · nextCursor=c1
→
album(create, "萌宠", ${r1.ids})
→
r2 · albumId
→
播报「正在查找照片，需要一些时间」
第 2…N 轮
search(猫猫, cursor=${r_prev.nextCursor})续页 · 不出卡
→
rN · ≤500 ids · nextCursor
→
album(append, ${r2.albumId}, ${rN.ids})
有 nextCursor → 模型继续下一轮 nextCursor = null → 结束，相册 Skill 出汇总卡「已整理 2 万张到萌宠」
为什么不「攒齐再 create」
2 万张本来就过不了「一次 ≤500」的边界；模型还要合并 40 个 ${r.ids}，引用没有拼接语义。边搜边 append 每次 ≤500，中断可续。
为什么不在相册 Skill 里判「前序搜索有没有 cursor」
相册 Skill 运行时去读搜索结果 = 跨 Skill 依赖；且它判完也只是让模型去继续搜，而搜索返回的 nextCursor 已经是这个信号。
继续 / 停止的规则放哪
搜索 Skill 说明：「返回 nextCursor 即未找全；整理场景先 append 本页再带 cursor 继续；null 即结束」。相册 Skill 说明只提一句「多轮用 append 不重复 create」（prompt 层 reference，非运行时依赖）。

场景 2 · 接续整理「把剩下的猫猫也整理到萌宠」「再搜下狗狗也整理到萌宠」— 靠 organize 的相册过滤，不用 cursor

search(狗狗 | 猫猫, mode=organize, target_album="萌宠")organize 自动过滤：不在萌宠相册里的，就是「剩下的」/「新的」
→
r1 · 增量 ids · nextCursor
→
album(append, "萌宠", ${r1.ids})按名解析到已有相册
→
增量移入超 500 → 叠加场景 1 的 cursor 循环
为什么接续不用 cursor
接续可能隔几分钟也可能隔天：cursor 会过期，期间新拍照片会打乱顺序。按目标相册过滤是无状态的、天然去重、重放安全；cursor 只在同一任务的循环内用。
传相册名还是 albumId
模型侧传名（用户原话、短字面量）；同一会话刚建完有 ${r.albumId} 就用引用。工具侧统一按名解析成 id；同名多相册短路让用户选，不静默猜。

搜索结果卡片：整个流程只出一张

不做 ×

每轮搜索都出卡 → 2 万张出 40 张卡；或单独加 show_card=false 让模型每轮记得传 → 遗漏一次就多一张卡。

搜索侧 ✓

mode=organize 一次表达「不出卡 + 返回 cursor + filter(不在目标相册中) + ids mask」，模型只需多传一个 mode 和目标相册；带 cursor 的续页请求工具侧自动不出卡，不依赖模型遵从。浏览场景（默认 mode）照常出卡。

相册侧 ✓

流程结束由相册 Skill 出一张汇总卡：「已整理 20 000 张猫猫到萌宠相册」+ 封面。用户全程只看到一张卡，比现状体验更好。

改动清单与护栏

处改动
搜索 Skill加 mode / cursor / target_album（名或 id）；organize = 不出卡 + 返回 nextCursor + 过滤已在目标相册的照片 + ids mask；续页不出卡；说明里写循环规则
相册 Skillcreate / append 为现有规格，不改接口；确认 target 可按名解析、append 去重（缺则补）；结束出汇总卡；说明里写「多轮用 append 不重复 create」
模型 / Skill 说明「有 nextCursor 就 append 后继续搜，null 即停」；max_rounds 上限；每轮进度播报、可取消
护栏终止靠 nextCursor（工具事实）不靠模型感觉；ids 全程 mask；cursor 不跨轮使用；exclude 以相册实时内容为准（append 落库后再发下一轮）
不做相册 Skill 运行时读搜索结果；攒齐 2 万再 create；模型记页码；Skill 调 Skill
成本 / 后续2 万张 ≈ 80 次 tool call。契约钉住后，搜索侧可做服务端 fetch_all 把循环压回 1～2 次，模型侧无感
两组原语　search(mode=organize / cursor / target_album)　album(create / append ≤500, 去重)
循环内用 cursor，接续靠相册过滤　停止靠 nextCursor=null
只出一张卡　搜索不出，相册结束出汇总
