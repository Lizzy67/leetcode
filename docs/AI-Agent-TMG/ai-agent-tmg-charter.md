## 1. 定位（一句话）

AI Agent TMG 负责终端 BG **智能体领域架构看护与技术方案评审**，制定面向智能体的 **工具与技能（Tool / Skill）体系** 技术方案、研发规范与标准；**不替代**项目排期决策，**不替代** SEG 系统工程评审与 DRB 重大设计拍板。

---

## 2. 组织职责

1. **架构看护**：系统智能体与各应用智能体（如小艺主对话、图库/相机/看世界等应用智能体）的架构边界、分层与演进一致性。  
2. **技术方案评审**：领域内关键/跨模块智能体方案的技术可行性、兼容性、风险与落地路径评审。  
3. **工具与技能体系**：Tool / Skill 契约、版本与配套策略、能力注册与调用链路等技术方案把关。  
4. **规范与标准**：研发规范、接口/契约标准、变更准入与异常处理基线的制定、发布与修订。  
5. **技术债与风险治理**：识别共性技术债与高风险变更，推动收敛或升级。

---

## 3. 管什么 / 不管什么

| 管（必须过 TMG 或遵从 TMG 标准） | 不管（不在此拍板） |
|----------------------------------|--------------------|
| 智能体领域公共架构与跨应用边界变更 | 日常需求优先级与人力排期 |
| Tool / Skill 破坏性变更（MAJOR / 删改契约） | 单点业务功能细节实现选型（无架构影响时） |
| 工具与技能体系规范、版本与兼容策略 | 纯运营配置、文案与活动策略 |
| 跨系统/应用智能体的统一技术标准 | 已由 SEG/DRB 正式决议且无需修订规则的事项 |
| 高风险方案（安全、兼容、性能底线、不可回滚）前置意见 | 人事与行政事项 |

---

## 4. 与 SEG / DRB 的关系

```text
SE / 业务提出方案
  → 遵守 TMG 已发布规范与标准
  → 属 TMG 准入范围：提交 AI Agent TMG 评审/决议
  → 跨领域系统拉通、复杂系统工程问题：升级 SEG
  → 重大架构取舍 / 正式设计准入：升级 DRB
```

- **TMG**：领域规则 + 智能体/Tool·Skill 技术方案评审与准入意见  
- **SEG**：跨领域系统工程拉通与专业评审  
- **DRB**：重大设计决策与正式拍板  

争议在 TMG 内无法收敛时：**带不超过 3 个选项 + 利弊** 升级 SEG/DRB，不长期空转。

## 6. 运作机制

### 6.1 节奏

- **双周例会**：45–60 分钟；只决策，不开放式务虚。  
- **材料截止**：会前 **24–48 小时** 提交（背景、选项≤3、影响面、建议决议）。  
- **纪要**：会后 **24 小时内** 发出（决议、Owner、截止日期、是否升级）。  
- **紧急加会**：仅限已触发「紧急准入」标准的破坏性变更或线上架构风险。

### 6.2 决议效力

- TMG 决议对领域内相关团队 **默认生效**；执行 Owner 必须明确。  
- 与已发布标准冲突的特例，须记入纪要并设 **有效期 / 退出条件**。  
- 需修订正式标准时，走「标准修订」议题，发布后纳入规范库。

### 6.3 三张清单（秘书维护）

1. **准入清单**：哪些变更必须过 TMG  
2. **标准清单**：已发布规范与版本  
3. **决议跟踪清单**：Open / Done / Escalated  

---

## 7. 建议首批准入范围（可首期会上确认）

1. 系统智能体 ↔ 应用智能体 公共边界、主对话 / inapp / onapp 协同架构变更  
2. Tool / Skill：**MAJOR、删除、改名、契约不兼容变更**  
3. 工具与技能配套/兼容策略、能力注册与调用主路径变更  
4. 智能体领域公共能力标准（如结果引用传参、分身接入、快慢系统协同等）口径变更  
5. 可能造成大面积兼容、安全或不可回滚风险的方案  

---

## 8. 决策原则

1. **兼容优先**：能平滑演进则不做破坏性变更。  
2. **规则一致**：同类问题同标准，少开永久特例。  
3. **可灰度 / 可回滚**：无退路方案从严。  
4. **材料说话**：无选项对比与影响面，不进入决策。  
5. **闭环追责**：每项决议有 Owner 与时间点。
