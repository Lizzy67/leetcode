## 技术领域

本发明属于人工智能与智能体（Agent）编排技术领域，具体涉及大语言模型（LLM）在多轮、多工具调用过程中，对工具返回结果进行缓存、引用、掩码展示，以及在工具实际执行前进行变量解析与真值回填的方法及系统。

---

## 背景技术

现有基于大模型的 Agent 系统通常采用「模型决策 → 发起工具调用 → 将工具结果再次输入模型 → 模型再决策」的循环。当工具返回体量较大（例如长 URI、文件标识、结构化大字段、长文本）时，至少存在以下问题：

1. **输入代价高**：完整结果反复进入模型上下文，导致 Input Token 膨胀、时延与成本上升。  
2. **传参遵从性差**：下游工具若需要沿用上游结果中的字段，常要求模型「原样抄写」长字符串，易出现截断、改写、漏字符、大小写错误等。  
3. **部分字段无需模型理解**：如 `fileUri`、`fileId` 等指针型数据，往往仅作为下一工具的输入句柄，模型只需感知「存在可引用变量」，无需阅读其具体内容。  
4. **跨组件标识不统一**：供应商侧 `toolCallId` 通常较长且格式不一，不适合直接作为模型侧引用标识；若各子系统各自生成短 ID（例如随机 UUID 截断），则难以对齐与复现。

现有思路包括：对话压缩/裁剪、将大结果落盘后仅回传摘要、或依赖模型自行记忆。上述方式或损失可引用精度，或仍要求模型抄写长值，或缺乏在工具执行前由运行时统一展开引用的机制。

因此，需要一种面向工具链的**结果默认入记忆、模型侧短引用、执行侧回填真值**，并支持按字段掩码与多级约束的方法。

## 发明内容

### 要解决的技术问题

在多轮工具调用场景下，如何在不迫使模型复述长结果值的前提下，稳定、低成本地完成跨工具的数据传递，并兼顾「模型无需看见真值」与「模型需要看见真值但仍需引用传参」两类场景，同时兼容不同工具结果存储形态。

### 技术方案概要

本发明提供一种方法及系统，核心包括：

1. **默认入库**：工具调用成功返回后，运行时/对话管理模块（DM）将结果写入工作记忆（workmemory），并分配模型侧短标识 `resultId`，同时保留与内部调用标识（如 `toolCallId`）的映射。  
2. **引用语法**：模型在后续工具入参中输出引用占位符，形如 `${resultId.jsonpath}`；其中 `resultId` 仅含字母数字且不含 `.`，以首个 `.` 分隔字段路径。  
3. **执行前回填**：在 invoke/exec 之前，运行时解析入参中的引用，按查找顺序在结果存储中取值并替换为真值后再调用工具。  
4. **掩码呈现（mask）**：送入模型前，可按**通用字段规则 + 单工具配置**将指定字段替换为引用占位符（或会话内短句柄），使模型所见即所填。  
5. **多级约束**：掩码硬约束、Skill/参数 schema 约束、系统提示软约束相配合，降低长值照抄。  
6. **兼容查找**：解析时优先查全量工具返回集合（如 `resultDataList`），再查已适配视图（如 `dataForTool`）。

### 有益效果

- 降低多轮工具链的 Input Token 与时延；  
- 以短占位符替代长字符串抄写，提高传参遵从性与正确性；  
- 指针型字段可对模型不可见但仍可被下游工具正确消费；  
- 真值由运行时注入，减少截断与篡改；  
- 通过统一短 `resultId` 与内部 `toolCallId` 解耦，便于跨模型供应商与多系统对齐；  
- 对存量「已适配工具面」与「全量返回面」双存储兼容。

## 具体实施方式

### 实施例1：系统组成

一种工具结果变量引用系统，包括：

1. **模型交互模块**：向大模型提供上下文，接收工具调用请求（含参数）。  
2. **编排/对话管理模块（Runtime/DM）**：负责工具调度、结果入库、送模前掩码、入参引用解析与回填、错误反馈。  
3. **工作记忆模块（Workmemory）**：按会话（或等价作用域）存储工具结果，至少支持：  
   - 全量结果集合（记为 `resultDataList` / 等价结构）；  
   - 可选的工具适配视图（记为 `dataForTool` / 等价结构）；  
   - `resultId` 与 `toolCallId`（及可选 provider、sessionId）的映射。  
4. **工具执行模块**：基于回填后的真实参数执行工具，并返回结果。

### 实施例2：端到端流程

**S1 工具执行与入库**  
工具执行完成并成功返回后，DM 将结果写入 workmemory，生成 `resultId`，并建立与本次 `toolCallId` 的映射。

**S2 送模前处理**  
根据通用 mask 配置与该工具的覆盖配置，决定各字段对模型的可见性：  
- 需屏蔽的字段：用占位符替换真值（见实施例4）；  
- 需供推理的字段：保留真值或摘要，并可同时提示可引用路径。

**S3 模型产出下一工具调用**  
模型在参数中填写引用占位符，而非长真值（在掩码场景下通常原样回传所见占位符）。

**S4 引用解析与回填**  
在实际 invoke/exec 前：  
1. 识别参数值是否匹配引用语法；  
2. 解析 `resultId` 与 `jsonpath`；  
3. 先在 `resultDataList` 中查找，未命中再在 `dataForTool` 中查找；  
4. 命中则替换为真值；未命中或语法非法则返回明确错误，避免将字面量 `${...}` 误传下游。

**S5 执行与闭环**  
使用回填后的参数调用工具；成功则再次执行 S1，形成多轮闭环。

### 实施例3：引用语法与 resultId

**引用格式**：`${resultId.jsonpath}`  

- `resultId`：模型侧短标识，字符集限定为字母与数字，**不含** `.`，以便用首个 `.` 无歧义切分路径。  
- `jsonpath`：字段路径，支持点号嵌套（实现上可先支持简单字段名，再扩展受限路径子集）。  

**推荐生成方式（确定性）**：由 DM 唯一生成，例如  

`resultId = hex8(Hash(toolCallId))`  

或在跨会话共享存储时：  

`resultId = hex8(Hash(sessionId || toolCallId))`  

其中 Hash 可为 FNV-1a-64、SHA-256 等；`hex8` 表示取 8 位十六进制（可扩展为 12 位以降低碰撞概率）。

**与 toolCallId 的关系**：  
`toolCallId` 作为内部关联键保留；不直接作为模型侧引用 ID，以避免过长、格式不一及抄写错误。系统维护双向映射。

**可选短句柄**：会话内分配 `${r1}`、`${r2}` 等不透明句柄，mask 时展示句柄，DM 将其映射到 `(resultId, path)`；模型仍遵循「所见即所填」。

### 实施例4：掩码（mask）策略

**通用默认规则**：对指针型/无需模型阅读的字段名或模式默认掩码，例如（示例性非穷尽）：`fileUri`、`fileId`、`objectId`、匹配 `*Url` 的字段等。

**工具级覆盖**：单个工具可增加或减少掩码字段；合并优先级为：**工具配置优于通用默认**。

**掩码形态**：替换后的字符串应为模型回传目标（所见即所填），优先使用：  
- `${resultId.jsonpath}`，或  
- 会话短句柄 `${rN}`（由 DM 映射）。  

避免对多个不同字段使用完全相同的无区分死标记（例如一律 `<MASKED>`），以防歧义。

### 实施例5：两种可见性场景

**场景①：模型不需要看见 value**  
送模前对字段掩码。模型仅感知变量/占位符，并在下游入参中原样引用。适用于 URI、文件 ID 等。

**场景②：模型需要看见 value**  
向模型暴露真值或摘要以支持推理；但通过 Skill/参数约定（例如标记可引用、或要求入参必须为引用形态）约束其在工具入参中仍输出占位符，实现「看」与「传」分离。

### 实施例6：系统提示软约束（可选）

在系统提示中约定：当参数取值来自已有工具结果字段时，禁止复述长值，应输出引用占位符；若上下文中该字段已被呈现为 `${...}`，则原样复制。对较长值（例如超过预设 token 阈值）禁止照抄。该约束为软约束，与掩码、Skill 硬约束配合，优先级建议为：

**掩码展示 > Skill/Schema 约束 > 系统提示**。

### 实施例7：参数枚举辅助（可选）

在发起下一工具前，DM 可将当前会话中可引用项动态写入参数 schema 的枚举（enum）或等价候选列表，使模型从合法引用集合中选择，而非手写拼装，进一步降低错误率。并行多工具场景下，优采用枚举或显式 `resultId`，避免歧义的「默认上一条」。

### 实施例8：装置与介质

与上述方法步骤一一对应的装置模块、电子设备（处理器+存储器）以及存储有指令的计算机可读存储介质，均构成本发明实施方式。

### 权利要求1（独立方法）

一种工具调用结果的变量引用与回填方法，其特征在于，包括：

在工具调用返回成功后，将工具结果写入工作记忆，并生成供模型使用的结果标识 `resultId`；

在将工具结果提供给大模型之前，根据配置对选定字段进行掩码，使所述选定字段在模型上下文中以引用占位符形式呈现；

接收大模型发起的后续工具调用请求，所述请求的参数中包含引用占位符；

在执行所述后续工具调用之前，解析所述引用占位符，从所述工作记忆中查找对应真值并回填到参数中，再执行工具。

### 权利要求2

根据权利要求1所述的方法，其特征在于，所述引用占位符的形式为 `${resultId.jsonpath}`，其中 `resultId` 仅包含字母与数字且不包含点号，所述 `jsonpath` 为字段路径。

### 权利要求3

根据权利要求1所述的方法，其特征在于，所述查找包括：优先在全量工具返回集合中查找，未命中时再在工具适配数据集合中查找。

### 权利要求4

根据权利要求1所述的方法，其特征在于，所述掩码配置包括通用字段规则与单工具覆盖规则，且单工具覆盖规则优先于通用字段规则。

### 权利要求5

根据权利要求4所述的方法，其特征在于，所述通用字段规则至少针对文件 URI、文件标识或对象标识类指针字段进行默认掩码。

### 权利要求6

根据权利要求1所述的方法，其特征在于，所述 `resultId` 由运行时根据内部工具调用标识确定性哈希截断生成，并存储 `resultId` 与所述内部工具调用标识的映射；所述内部工具调用标识不直接作为模型侧引用标识。

### 权利要求7

根据权利要求1所述的方法，其特征在于，所述掩码后的占位符为会话内短句柄，所述短句柄由运行时映射到 `resultId` 与字段路径；模型将上下文中看到的占位符原样作为参数值输出。

### 权利要求8

根据权利要求1所述的方法，其特征在于，对于需要模型阅读的字段，向模型暴露真值或摘要，同时通过工具参数约束要求后续入参仍使用引用占位符。

### 权利要求9

根据权利要求1所述的方法，其特征在于，在构造后续工具的参数模式时，将当前可引用结果写入参数枚举或候选列表，供模型选择。

### 权利要求10

根据权利要求1所述的方法，其特征在于，当引用解析失败时，向大模型返回明确错误信息而不将未展开的占位符字面量传递给下游工具。

### 权利要求11（独立系统）

一种工具调用结果的变量引用与回填系统，其特征在于，包括工作记忆模块、编排模块与工具执行模块，所述编排模块用于执行权利要求1至10任一项所述方法的步骤。

### 权利要求12（独立设备/介质）

本发明公开一种工具调用结果的变量引用、掩码呈现与执行前回填方法及系统。工具返回结果默认写入工作记忆并分配短结果标识；向模型展示前可按通用规则与工具配置对指针型等字段掩码为引用占位符；模型在后续工具入参中输出占位符而非长真值；运行时在工具执行前解析占位符，按全量结果集优先、适配视图其次的顺序回填真值。本发明可降低多轮工具链的输入开销，提高跨工具传参遵从性与正确性，并兼容模型无需看见真值与需要看见真值两类场景。

```text
# 工具结果引用约定

工具参数若应使用「已有工具结果里的某个字段」，不要复述、改写或猜测该值；请填引用占位符，系统会在执行前回填真实值。

## 怎么填
1. 上下文里该字段若已是 `${...}` 占位符（含被 mask 的值）：原样复制到参数里，不要改写。
2. 否则写成：`${<resultId>.<字段路径>}`
   - `<resultId>`：只从上下文中已有工具结果读取（一般为 8 位字母数字），禁止编造。
   - `<字段路径>`：结果内字段，支持点号嵌套，如 `entityId`、`data.fileUri`。
3. 占位符必须是整个参数值：勿省略 `$`/`{`/`}`，勿前后拼接其它文字。

## 必须用引用
- 参数说明要求引用，或取值来自已有工具结果字段；
- 字段已被 mask，或值较长（约 >12 token，如 URI、fileId、大段文本）。

## 仍用字面值
- 来自用户原话，或可独立确定的短信息（相册名、数量、开关等），且不是某工具结果字段的拷贝。

以各工具参数说明为准；有可选枚举时，优先选枚举中的引用项。
```
