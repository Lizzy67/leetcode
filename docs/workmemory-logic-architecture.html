逻辑架构图 · workmemory 引用填参

工具结果默认入记忆 · Skill 显式 ${resultId:param} 引用 · DM 在 invoke 前解析填参

① 会话层 ② DM / Runtime ③ workmemory ④ Skill / 工具
① 会话层

模型 / LLM

  • plan / 发起工具调用
  • 只见短摘要 + resultId
  • 下游入参可写 ${resultId:param}

端侧（可选）

  • 从 dataForTool 取长 URI 等
  • 打开 / 展示给用户
  • 大字段不必回灌模型
↓
② DM / Runtime（平台能力）核心

写入 workmemory

  • 工具执行结束后默认缓存
  • resultId → resultData
  • 可选 dataForTool

回灌控制

  • 只把短摘要 + resultId 回给模型
  • 大字段不进 prompt
  • 降低 input token / TTFT

引用解析

  • 仅 x-ref: true 参数
  • 格式 ${resultId:param}
  • 先 resultData，再 dataForTool

invoke / exec

  • 替换入参后再调 Skill/工具
  • 解析失败则明确报错
  • 工具侧无感
↓ 读写
③ workmemory（会话级）

resultDataList / resultData 主源

  • 工具业务返回结果（JSON 可寻址）
  • 引用解析主数据源
  • 按 resultId 索引

dataForTool（可选）

  • 附加数据（如长 authorize_url）
  • 主源未命中时再查
  • 可给端侧直接消费
④ Skill / 工具

Skill Schema

  • 特定参数声明 x-ref: true
  • 允许入参写 ${resultId:param}
  • 未声明参数不解析引用

业务工具实现

  • 无感：不负责解析 $ 引用
  • 只消费 DM 替换后的真实入参
  • 结果默认回写 workmemory

数据流（端到端）

STEP 1执行工具 A，生成 resultId_A
STEP 2DM 写入 workmemory（resultData + dataForTool）
STEP 3回灌模型：摘要 + resultId_A
STEP 4模型调工具 B，入参 ${resultId_A:param}
STEP 5DM 解析填参 → invoke 工具 B
一句话： 工具结果 → workmemory →（模型只见摘要）→ 下游 ${resultId:param} → DM 解析填参 → 再调工具
resultId：字母数字（如去横线 UUID） · 引用格式：${resultId:param} · 建议正则：^\$\{([A-Za-z0-9]+):([A-Za-z0-9_]+)\}$
