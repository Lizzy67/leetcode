逻辑架构图 · workmemory 引用填参

工具结果默认入记忆 · 语法 ${resultId.jsonpath}（resultId=UUID）· Runtime policy mask · 执行前递归解析

① 会话层 ② DM / Runtime ③ workmemory ④ Skill / 工具
① 会话层

模型 / LLM

  • plan / 发起工具调用
  • 只见短摘要 + UUID resultId
  • 下游入参可写 ${resultId.jsonpath}

端侧（可选）

  • 从 dataForTool 取长 URI 等
  • 打开 / 展示给用户
  • 大字段不必回灌模型
↓
② DM / Runtime（平台能力）核心

写入 workmemory

  • 工具结束后默认缓存；生成 UUID
  • 不可见值 → extendData 持久化
  • 可见值 → 仅内存 + 工作区

回灌 / mask

  • Runtime 绑定 CapturePolicy
  • 指针字段 mask 为 ${uuid.path}
  • 大字段不进 Provider request

引用解析

  • 递归遍历入参 JSON
  • 整体引用 + 值内引用
  • 先 resultData，再 dataForTool

invoke / exec

  • 执行副本中还原真值
  • 解析失败 fail closed
  • 工具侧无感
↓ 读写
③ workmemory（会话级）

resultDataList / resultData 主源

  • 工具业务返回结果（JSON 可寻址）
  • 引用解析主数据源
  • 按 resultId 索引

dataForTool（可选）

  • 附加数据（如长 authorize_url）
  • 主源未命中时再查
  • 可给端侧直接消费
④ Skill / 工具

Skill Schema

  • 特定参数声明 x-ref: true
  • 允许入参写 ${resultId.jsonpath}
  • Prompt/Skill 约束「看」与「传」分离

业务工具实现

  • 无感：不负责解析 $ 引用
  • 只消费 DM 替换后的真实入参
  • 结果默认回写 workmemory

数据流（端到端）

STEP 1执行工具 A，Runtime 生成 UUID resultId
STEP 2DM/太初写入 WM；不可见值进 extendData
STEP 3按 policy mask 后回灌模型
STEP 4模型调工具 B，入参 ${uuid.jsonpath}
STEP 5递归解析填参 → invoke 工具 B
一句话： 工具结果 → UUID 引用投影 →（模型只见短 token）→ 下游 ${resultId.jsonpath} → 执行前还原 → 再调工具
