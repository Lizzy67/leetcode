工具调用异常处理方案

语音助手按 Skill 调度工具时，模型可能生成不存在或不匹配端侧能力的工具调用：一类是模型幻觉（工具集之外的名字），一类是版本 / 端能力缺口（Skill 有声明，当前 ROM / 应用上不存在）。DM 先校验工具集，再按端错误码分流。

主流程

原则①：不在 Skill 工具集 → 幻觉 → 提示换工具（已支持） 原则②：在工具集、端报不存在 → 不重试 → 友好答复 成功 / 正常收口

方案一：单 Skill 收编（Runtime / DM 执行前校验）

Step1
DM 判断工具是否在 Skill 工具集：有则下发端；无则重新 Load Skill + notion，提示模型换个工具
DM
Step2
收到执行指令后，端返回不支持 / 工具不存在错误码（意图框架端工具需新增「工具不存在」错误码；CLI 已支持）
端
Step3
DM 收到端返回的错误码后追加 notion，引导模型做友好答复
DM

方案二：平台兜底（不阻塞过点）

  • 原则③仅按 ROM 大版本配置 Skill
  • 需要快速干预时才用白名单
  • 平台已支持 Skill 配置版本白名单，支撑 ROM 小版本场景

后续（待定）

  • 意图框架工具已可在 IDS 查询端版本是否具备该能力
  • 小艺封装工具、CLI、MCP 等按需在平台基于版本配置管理
  • 用于 DM 执行工具调度前检查工具是否存在（前移拦截）
一句话：不在 Skill 工具集就提示换工具；在工具集但端报不存在就不重试，按错误码友好答复「当前版本不支持」。
