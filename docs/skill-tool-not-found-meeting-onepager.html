工具调用异常处理 · 流程图

模型按 Skill 调度工具时，可能幻觉出工具集外的名称，或调用了 Skill 有、但当前端版本不存在的工具。DM 先校验工具集，再按端错误码分流：幻觉可换工具；端不存在则不重试并友好引导。

主流程

与纪要对齐的三步

Step1
DM 判断是否在 Skill 工具集：有则下发端；无则 Load Skill + notion 让模型换工具
@夏捷
Step2
端返回不支持/工具不存在错误码（意图框架需新增「工具不存在」错误码）
@李伟峰
Step3
DM 按错误码追加 notion，引导模型说明「当前版本不支持」等（场景1 不重试）
@夏捷

现状

  • CLI & ArkTS 已支持上报「工具不存在」错误码
  • IDS 已支持查询应用级意图框架接口能力是否存在

结论

  • 场景2幻觉 → 换工具（已支持）
  • 场景1端不存在 → 不重试 + 友好引导
  • ROM 小版本配 Skill 作兜底，不挡过点
一句话：先看在不在 Skill 里——不在就换工具；在但端说没有，就是当前版本不支持，说明白就结束，别空转。
