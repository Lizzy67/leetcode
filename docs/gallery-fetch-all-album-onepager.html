「把所有猫猫照片建一个相册」怎么接进现有编排

搜索 Skill 默认一次 500 张；2 万张要翻 40 页。问题只有一个：这 40 次翻页放在哪一层。

问题：现有链路只拿到第一页

模型「所有猫猫照片建相册」
→
搜索 Skill默认 SOP · 500 / 页
→
workmemory r1merged_id_list（仅 500）· hasMore=true
→
模型createAlbum(items=${r1.merged_id_list})
→
相册只有 500 张剩余 19 500 张丢失

约束：① 2 万个 ID 不能进模型上下文　② 裸搜索 Tool 能力不完整，只有搜索 Skill 是完整的　③ 当前架构不支持 Skill 调 Skill

三个候选：翻页循环挂在谁下面

B · 相册 Skill 内部去搜 当前做不对

↓

只调 1 次很诱人，但相册内只能调不完整的 Tool（结果和搜索 Skill 不一致），要补齐就得复制一套搜索逻辑；想改成委托搜索 Skill 的 SOP，就是 Skill 调 Skill，当前不支持。且相册变成「搜+建」复合体，入参变胖、只服务建相册。

C · 搜索 Skill 加全量 SOP 采用

模型 · fetch_all_search("猫猫")
↓
搜索 Skill 执行层内部翻 40 页攒齐 → 一个结果
↓
r1 · 20 000 ids（mask）
↓
模型 · createAlbum(${r1…})

全量 / 默认是同一搜索能力的两种规格，放在搜索 Skill 最自然。模型仍是 2 次调用，相册 Skill 零改动，拼图 / 笔记也能复用同一个全量结果。
