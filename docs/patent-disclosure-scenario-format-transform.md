## 应用场景概述

本发明适用于智能体多轮工具调用中的参数引用与执行前处理，典型应用场景包括：

### 场景 A：跨工具结果传递（同构或标量字段）

上一工具返回文件地址、对象标识等，下一工具需要相同或同构字段作为入参。模型填写结果引用占位符，运行时从工作记忆展开真值后执行。

### 场景 B：弱语义业务标识（如应用包名）

模型填写语义实体引用（命名空间.实体.属性），运行时经别名归一与映射表得到真实包名等标识；映射命中时尽量一次业务调用完成。

### 场景 C：跨工具结果传递且入参需策略化格式转换（补充）

#### C.1 场景描述

工具 A 输出某一数据结构（例如字符串列表或数值标识列表，字段名可为 `merged_id_list`）。工具 B 的对应入参（例如 `images`）要求另一种结构（例如对象列表，每一项为包含 `file_id` 字段的字典）。上下游 schema 不一致。

若由大模型读取列表并逐项改写为对象数组再写入工具 B，则当列表较长时，容易出现截断、遗漏、类型错误（数字与字符串混用）或字段名错误。若通过修改工具 A 的输出格式或工具 B 的输入协议消除差异，则在工具数量多、协议已固化时改造成本高、难以规模化。

#### C.2 本发明在该场景下的处理流程

1. **模型侧**：发起工具 B 调用时，对需要上游列表的参数仅填写结果引用占位符，例如将 `images` 的参数值设为对工具 A 结果中 `merged_id_list` 字段的引用，而不生成变换后的对象数组。  
2. **引用解析**：工具调度模块中的引用解析拦截器在工具执行前，将该占位符替换为工作记忆中的真实列表值，例如得到 `[563, 563, …]`。  
3. **策略化格式转换**：在引用回填成功之后、工具 B 真正执行之前，调度模块根据该工具该参数预先配置的转换策略（policy），对已回填的参数值执行结构变换。转换策略的语义为：将列表中的每个元素映射为一个字典，字典中预设键（例如 `file_id`）的值为该元素的字符串形式，最终得到对象列表。  
4. **工具执行**：将转换后的参数提交工具执行模块，工具 B 接收例如 `[{"file_id":"563"}, {"file_id":"563"}, …]` 并完成业务逻辑。

#### C.3 流程示意

```text
模型输出工具调用：
  arguments.images = ${resultId.merged_id_list}

        │ ① 引用解析（工作记忆）
        ▼
  images = [563, 563, …]

        │ ② 按 policy 格式转换
        │    逐元素 → {"file_id": string(元素)}
        ▼
  images = [{"file_id":"563"}, {"file_id":"563"}, …]

        │ ③ 调用工具 B
        ▼
  工具 B 执行（无感引用与转换）
```

#### C.4 转换策略的正确语义说明

转换应保证：

1. 先完成引用展开，再对**展开后的列表**做变换；或在转换表达式内对引用做逐元素解析，但不得对整个列表做一次字符串化后当成单一元素。  
2. 对列表中每一个元素分别构造字典，键名与下游工具约定一致（例如统一为 `file_id`）。  
3. 元素到字符串的类型转换按下游 schema 要求执行（若下游要求字符串型标识，则对数值元素进行字符串化）。

一种等价于策略意图的自然语言描述为：  
“将引用展开得到的列表中的每个元素 `item`，转换为一个包含字段 `file_id` 且值为 `string(item)` 的对象，并保持列表顺序，作为参数 `images` 的最终值。”

#### C.5 本场景的技术效果

1. 模型只需输出短引用，不必生成或抄写可能很长的对象数组，降低遵从性错误与上下文开销。  
2. 上游工具输出结构与下游工具入参结构通过执行前策略转换解耦，工具实现可保持不变。  
3. 引用解析与格式转换均位于统一调度入口，可对配置了相应策略的参数自动生效，便于规模化覆盖。

## 实施例要点（可并入「具体实施例」作实施例十七）

**实施例十七：引用展开后的入参策略化格式转换**

本实施例是对实施例一的进一步优化，解决跨工具数据结构不一致的问题。

**组成：** 在工具调度模块中，引用解析拦截器之后增设或内置**参数转换单元**；转换单元读取工具参数策略配置（可与工具描述或独立 policy 存储绑定）。

**步骤：**

1. 拦截器完成引用占位符回填，得到中间参数集；  
2. 转换单元判断当前工具的各个参数是否配置了格式转换策略；  
3. 对配置了策略的参数，以回填后的值为输入执行变换（包括但不限于：列表映射、字典封装、标量类型转换、字段重命名）；  
4. 变换失败则短路并返回错误，不将半成品参数交给工具；变换成功则将最终参数交给工具执行模块。

**与实施例一的关系：** 本实施例不改变“模型只写引用、执行前求值”的主路径，仅在回填之后增加可选的结构适配阶段；无转换策略的参数行为与实施例一相同。

**图17（建议）流程图：** 引用解析 → 是否有转换策略 → 是则执行转换 → 调用工具；转换失败则短路。
