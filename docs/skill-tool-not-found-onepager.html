工具调用异常处理 · 一页说明

先判是否在 Skill 工具集：幻觉可换工具；在集内但端不存在则不重试，友好引导「当前版本不支持」。ROM 小版本配 Skill 作兜底，不挡过点。

现状

  • 意图不存在：-304 invalid_intent_error（名/参是否混报待确认，需端区分）
  • CLI / ArkTS：已支持返回「工具不存在」类错误码
  • 封装工具：按需平台配置（后续）

两个场景

  • 场景2Skill 无该工具 → 模型幻觉 → 提示换工具（已支持）
  • 场景1Skill 有、端无 → 版本不支持 → 不重试 + 友好引导

修改一流程（单 Skill 收编 · DM 校验）

Step1
模型生成 tool_call → DM 判断是否在 Skill 工具集内：有则下发端；无则 Load Skill + notion，让模型换工具。
Step2
端执行并返回结果；若不支持该工具，返回明确「工具不存在」错误码。
Step3
DM 按错误码追加 notion → 提示模型做用户引导（例：当前版本不支持）+ 融合答；不再换工具重试。

① 不在工具集幻觉

notion：换 Skill 内工具 → 可有限次再决策（已支持）

② 在集内·端不存在

notion：当前版本不支持 → 友好答复收口，禁止空转

修改二 · 平台兜底

  • 按 ROM 小版本配置对应 Skill（已支持）
  • 原则：小版本不支持多 Skill；大版本才支持多 Skill
  • 不便比大小时：黑白名单
  • 节奏先走修改一过点，不阻塞

进一步 · 待定

  • Router（端/云 invoke）执行前查是否支持
  • 意图框架新增「工具不存在」错误码
  • CLI/ArkTS 对齐 DM；封装工具平台化
一句话：不在 Skill 里 → 幻觉，换工具；在 Skill 里但端说没有 → 当前版本不支持，不重试，把用户说明白。
