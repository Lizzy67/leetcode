找不到工具时怎么处理

端意图、端 CLI、云 MCP 幻觉乱调时走同一套：统一错误码 → 有限反思 → 产品话术收口。差异只在谁解析、谁执行。

主流程（全通道同一套）

tool_call → 按 kind 预检 → 执行器 → TOOL_NOT_FOUND → 反思 ≤1 → 产品话术结束
  • 包含 intent / cli / mcp（及 arkts）：上层策略相同，不是只覆盖意图工具
  • 统一 error_code=TOOL_NOT_FOUND，回传带 kind 的 allowed_tools
  • 超次或再次白名单外点名 → 立即话术收口，禁止 Loop

分通道谁判“不存在”

  • intent：ToMP ∩ 端能力 → 端执行器
  • cli：CLI 目录 ∩ 端能力 → 端 CLI
  • mcp：会话 list_tools ∩ 授权 → 云 Gateway
  • MCP 未挂载/断开 → 宜用 TOOL_UNAVAILABLE

Skill / 产品要配的

  • 默认话术可覆盖全通道；可选 by_kind
  • allowed_tools 标明 kind（及 mcp server）
  • max_reflect_rounds 默认 1（硬顶 ≤2）
  • SOP：只许改调白名单，禁止再造工具名

和「工具不可用」区分

  • TOOL_NOT_FOUND：名字就不存在（幻觉/写错）→ 反思或话术
  • TOOL_UNAVAILABLE：工具有，但当前不可用（端裁剪 / MCP 未连接）→ 引导或降级
  • TOOL_SCHEMA_INVALID：工具有，参数错 → 按 schema 纠错
要点：通道不同，契约相同；标识可分支；话术产品提供；反思有预算；收口必须结束本轮。
