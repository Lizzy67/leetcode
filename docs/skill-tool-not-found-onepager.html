找不到工具时怎么处理

模型幻觉出不存在的工具时：统一错误标识 → 有限次反思纠错 → 产品话术收口，禁止空转 Loop。

主流程

tool_call → 云预检 → 端执行 → TOOL_NOT_FOUND → 反思 ≤1 → 产品话术结束
  • 预检与端返回使用同一语义：error_code = TOOL_NOT_FOUND
  • 结果带回 allowed_tools（及可选 suggestions），供模型改调
  • 超次或再次点名白名单外工具 → 立即话术收口

端 / 云要给的标识

  • 稳定码：TOOL_NOT_FOUND
  • reflectable / retryable
  • tool.requested 原始点名
  • hint.allowed_tools 本 Skill 白名单
  • source：cloud_precheck 或 device

Skill / 产品要配的

  • exception_handlers.TOOL_NOT_FOUND.user_utterance
  • 可选：反思用尽后的变体话术
  • max_reflect_rounds 默认 1（硬顶 ≤2）
  • SOP 写明：只能改调允许列表，禁止再造工具名

和「工具不可用」区分

  • TOOL_NOT_FOUND：名字就不存在（幻觉/写错）→ 反思或话术
  • TOOL_UNAVAILABLE：工具有，但本机能力不够 → 引导升级/降级
  • TOOL_SCHEMA_INVALID：工具有，参数错 → 按 schema 纠错
要点：标识要机器可分支；话术由产品提供；反思有预算；收口必须结束本轮技能路径。
