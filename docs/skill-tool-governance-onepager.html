Skill / Tool 配套治理 · 一页说明

可以有配套，但消灭人肉版本表；不配套时体验可控。匹配靠能力契约，灰度靠独立放量，工具按接口规范管。

1一句话方案

  • Skill 只声明依赖哪些 Tool（requires）
  • 端 上报实际能力（capabilities），Gate 做匹配
  • Tool 补齐元数据后，再自动推导 ROM/App 生效范围
  • 灰度 独立 Release，不再写进 Skill 的 ROM 框

2运行时三道门

Search 召回 → Compat 硬 → Rollout 软 → Load / Fallback
Compat capabilities ⊇ requires；同名取最高可跑版本
Rollout 白名单 / 百分比 / audience；未命中优先回退旧全量版
失败 不支持 → 拒答升级；不放量 → fallback；禁止长 Loop

3三件事拆开配

兼容 能不能跑 → requires + 端能力（远期从 Tool 推 ROM）
多版本 同名多 skill_version；requires 变严才出新版并存
灰度 先给谁用 → Release；可用 ROM 作 audience，不作永久配套

4Skill 怎么改

  • 必填 requires
  • 薄 env_gates（机型/包名/锁屏）
  • ROM 矩阵降级为 legacy，最终只读推导
  • 仅优化体验且依赖不变 → 覆盖发

5Tool 怎么管

  • 登记 tool_id / 契约版本 / schema / owner
  • 已上线行为冻结（2D API）
  • 新能力用 MINOR/feature，破坏走 MAJOR+TMG
  • 改 Tool 自动扫描依赖 Skill

6现状过渡

  • Tool 暂不配 ROM/App
  • 先跑：端能力匹配
  • 并行：ToMP 补热门 min_rom
  • 再切：Skill 范围自动推导

7落地节奏

P0发规范：三层配置 + Tool 冻结 + 拒答不 Loop
P1requires + capabilities + skillGate Compat；Release 放量拆出
P2ToMP 最小闭环 + ArkTS 收编 + 多版本 fallback
P3Tool 补 ROM/App 元数据 → 推导生效范围 → 退役人肉表
总纲：Skill 依赖 Tool，Gate 按端能力匹配；灰度走 Release；工具平台管契约与变更联动。人肉 Skill×ROM 配套表退出主路径。
