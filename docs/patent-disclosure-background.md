# 交底书 · 发明背景

**发明名称（建议）：** 一种面向智能体工具链的参数引用解析机制

---

## 发明背景

### 一、技术领域

本发明属于人工智能与智能体（Agent）编排技术领域，具体涉及大语言模型在多轮工具调用（Tool / Function Calling）过程中，对工具入参进行引用表达、调用前解析求值与真值回填的方法及系统。

### 二、应用场景

在基于大语言模型的智能体系统中，典型执行链路为：用户提出意图后，模型决策并发起工具调用；运行时执行工具并将结果返回模型；模型根据结果继续决策或再次调用工具。该模式在下列场景中尤为常见：

**场景一：跨工具结果传递。**  
上一工具返回文件地址（URI）、对象标识、大段文本等字段，下一工具需要以相同字段作为入参。例如：先上传/生成文件，再对文件进行分析、转发或渲染。

**场景二：弱语义业务标识作为工具入参。**  
以端侧应用操控为例，业务工具常要求填写应用包名（如 bundleName / packageName / bundleId）。包名命名不规范、语义性弱，用户口语多为「抖音」「微信」等应用名。按现有习惯，模型往往需要先调用「查询已安装应用列表」类工具获取真实包名，再调用权限管理、跳转等业务工具，形成两次循环；且相关工具数量多，难以逐个改造工具接口。

**场景三：跨工具结果传递且入参结构需格式转换。**  
上一工具返回某一数据结构（例如字符串列表或标识列表），下一工具要求的入参结构与之不一致（例如要求对象列表，每一项为包含 `file_id` 字段的字典）。若由模型完成“读取列表 → 逐项改写为对象结构 → 写入下一工具参数”，则列表稍长即易截断、改写或类型错误；若为每个下游工具单独改造上游输出或下游入参协议，则改造成本高。该场景需要在引用展开取得真实列表之后，由运行时按策略（policy）自动完成结构变换，再调用下游工具。

### 三、现有技术及存在的问题

针对上述场景，现有常见做法包括：

1. **完整结果回灌并由模型复述填参**：将工具返回的完整内容再次输入模型上下文，由模型在下一轮工具参数中原样抄写所需字段（如长 URI）。  
2. **先查询、再调用的两轮路径**：对包名等标识，要求模型先枚举/查询全量候选，再从中抄写真实标识后调用业务工具。  
3. **仅依赖提示词约束**：通过系统提示要求模型“不要编造包名”“不要改写 URI”，但真实字符串仍由模型直接生成。  
4. **工作流或提示词模板中的预置变量替换**：在编排脚本或提示模板中使用占位符，由引擎用预置状态变量填充；变量通常由编排侧预先写入，而非模型在工具调用实参中按统一协议表达引用意图。  
5. **运行时注入类参数（如用户身份、会话标识）**：将不应由模型填写的系统参数从工具 schema 中剥离，在调用时由运行时写入。该类机制主要解决鉴权与系统上下文安全问题，并不解决业务工具参数中“上游结果字段传递”以及“弱语义业务标识易幻觉”的问题。

上述做法至少存在以下缺陷：

**（1）多轮调用开销大。**  
为获取真实业务标识，常需额外增加查询类工具调用；大结果反复进入模型上下文，导致输入 token 增加、时延与成本上升。

**（2）模型遵从性差，易出错。**  
要求模型原样抄写长字符串时，容易出现截断、改写、漏字符等问题；对包名等弱语义标识，模型易凭训练记忆编造看似合理但错误的取值（幻觉），导致工具调用失败甚至误操作。

**（3）部分字段无需模型理解，却仍被迫暴露或抄写。**  
如文件 URI、对象 ID 等指针型数据，往往仅作为下游工具的输入句柄，模型只需感知存在可引用对象，无需理解其具体内容；现有链路缺乏统一的掩码呈现与引用回传机制。

**（4）跨工具数据结构不一致时，依赖模型做格式变换或依赖改工具。**  
上游列表、标量与下游对象数组、字段封装等结构不匹配时，若由模型生成变换后的大段结构化入参，出错率高；若逐个修改工具输入输出协议，难以规模化。

**（5）工具改造成本高，难以规模化。**  
带包名、文件地址等参数的工具数量多，若为引用能力逐个修改工具实现或参数协议，工程代价高、难以覆盖存量工具。

**（6）真实值权威仍落在模型侧，缺少结构性约束。**  
无论是提示词约束还是先查后抄，最终写入工具的业务真值仍主要由模型生成或复述，系统无法在执行前保证“真实标识只能来自可信数据源（会话结果记忆或映射词典）”，也无法在解析失败时统一阻止错误字面量进入工具。

### 四、本发明要解决的技术问题

因此，希望提供一种面向智能体工具链的参数引用解析机制，使得：

1. 模型在工具入参中只需表达引用意图（例如引用上一工具结果中的某字段，或引用某应用实体的包名属性），而不直接生成易幻觉、易抄错的业务真值；  
2. 运行时在工具真正执行前统一解析引用并回填真值，工具侧无需感知、无需改造即可覆盖同类参数；  
3. 在映射命中的正常路径下，尽量以一次业务工具调用完成任务，仅在无法解析时再走查询类兜底；  
4. 解析失败时短路并禁止将未展开的引用字面量透传给工具，从而提升工具链传参的正确性、安全性与效率；  
5. 在引用展开之后、工具执行之前，可按参数策略对已回填值做结构化格式转换，使上游结果结构与下游入参结构解耦，而无需模型改写结构、无需修改工具实现。
