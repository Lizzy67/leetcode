Workmemory 引用方案 · 一页纸

语法 ${resultId.jsonpath}
resultId = UUID.randomUUID().toString().substring(0, 8)

1. 背景

  • 精确值（URI / fileId / 大段文本）经模型多次搬运易抄错。
  • 模型输出非自然语言长值无意义且时延长。

场景① 值不可见 = 加 mask

  • 进模型前替换为 ${a1b2c3d4.fileUri}。
  • 模型只感知变量名，不看真值。
  • 精确值留在 Runtime 缓存，执行时还原。
典型：fileUri、fileId、长 URL

场景② 值可见 = 原样进模型

  • 原文原样输入给模型（供推理）。
  • 输出时仍按 SystemPrompt / Skill 只输出引用。
  • 由 Runtime 替换为真实值后再调下游工具。
例：先生成 Java 代码（可见）→ 再转 Python，入参用 ${e5f6a7b8.text}

2. 定稿原则

  • resultId：统一 UUID.randomUUID().toString().substring(0, 8)（取 32 位 UUID 字符串前 8 位）。
  • 引用场景分为 值可见 / 值不可见 两种（见上）。
  • 进模型前：按默认/工具 policy（+ 正则）加 mask；Runtime 缓存 resultDataList。
  • Skill / SystemPrompt：约束模型输出引用；加 mask 后只能出引用，禁止照抄原值。
  • Runtime 解析：递归遍历入参，整体/值内引用 → 查缓存还原真值；未命中 fail closed。

4. 逻辑架构

① 工具 A 返回产出精确结果
② Runtime 改写mask 并存 workmemory
③ 模型推理输出引用变量
④ Runtime 改回引用 → 真值
⑤ 调用工具 B使用真实入参执行

6. resultId 与入参替换

  • 生成算法统一：UUID.randomUUID().toString().substring(0, 8)。
  • 工具入参 JSON 递归遍历：整体变量引用 + 值内引用，再替换。
  • 查找：Runtime 缓存的 resultDataList（及必要的 dataForTool）。

7. SubAgent 特殊规则

  • 输出阶段对 URI 等加 mask。
  • hook 抽出自然语言中的 ${...}，随 memoryList 返回。
  • 输入 / 输出 mask 均不还原；裁 memoryList{名:值} 交回。
# 工具结果引用约定

工具参数若应使用「已有工具结果里的某个字段」，不要复述、改写或猜测该值；请填引用占位符，系统会在执行前回填真实值。

## 怎么填
1. 上下文里该字段若已是 `${...}` 占位符（含被 mask 的值）：**原样复制**到参数里，不要改写。
2. 否则写成：`${<resultId>.<字段路径>}`
   - `<resultId>`：只从上下文中已有工具结果读取（一般为 8 位字母数字），禁止编造。
   - `<字段路径>`：结果内字段，支持点号嵌套，如 `entityId`、`data.fileUri`。
3. 占位符必须是**整个参数值**：勿省略 `$`/`{`/`}`，勿前后拼接其它文字。

以各工具参数说明为准；有可选枚举时，优先选枚举中的引用项。
