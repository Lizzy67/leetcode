Workmemory 引用方案 · 一页纸

语法 ${resultId.jsonpath} · resultId 仅字母数字（无 .）

1. 背景

  • 大结果让模型原样抄回下一工具 → 遵从性差、Input Token 高。
  • URI 等只需当下游入参，模型不必理解内容，感知变量即可。
  • 送模前 Runtime/DM 可按工具配置把值 mask 成 ${resultId.jsonpath}。

2. 方案原则

  • 工具返回 默认写入 workmemory。
  • invoke/exec 前按模型引用 解析回填 真值。
  • 查找：先 resultDataList（全量），再 dataForTool（已适配）。

3. 关键点

  • 短引用替代抄长串 → 更稳、更省 token。
  • resultId 无 .，首个 . 切 jsonpath。
  • 引用未命中明确报错，勿原样传下游。

4. 流程

① 返回工具产出结果
② 入库写入 workmemory，生成 resultId
③ 送模按配置 mask 或不 mask
④ 出参模型写 ${id.path}
⑤ 回填resultDataList → dataForTool
⑥ 调用真值调工具，再入库

场景① 不看 value

  • 送模前 mask 为引用；模型只需感知变量。
  • 适用：URI、objectId 等指针字段。
送模 ${a1b2.fileUri} → 模型原样引用 → DM 回填真 URI

场景② 要看 value

  • value/摘要给模型推理；Skill 仍约束入参必须写引用。
  • 「看」与「传」分离。
可见 text → 入参仍写 ${e5f6.text} → DM 回填

5. 生命周期

  1. 创建：返回成功 → 分配 resultId → 入库
  2. 暴露：mask 或可见 + 可引用路径
  3. 引用 / 回填：模型输出 → invoke 前展开
  4. 失效：会话结束 / TTL / 清理；未命中报错

6. 收益

  • 降 Input Token → 降时延
  • 短引用 → 传参更遵从
  • 真值由 DM 注入 → 少截断/篡改
  • 两套存储兼容存量适配

7. 边界

  • 只解析工具入参
  • 一期可先简单字段名
  • 与 Preview 等能力正交
结果入 workmemory → 按需 mask → 模型只输出 ${resultId.jsonpath} → invoke 前按 resultDataList → dataForTool 回填。
