Workmemory 引用方案 · 一页纸

用引用代替复述大结果：降 Input Token、提传参遵从性；真值由 Runtime/DM 回填
语法：${resultId.jsonpath}
resultId：仅字母数字（不含 .）· 首个 . 后为 jsonpath

1. 背景

  • 多轮工具链里，上一步常返回 URI、大段正文等。若整段回灌并要求模型「原样抄回」下一工具入参，遵从性差（截断、改写、漏字符），且 Input Token 膨胀、时延上升。
  • 不少字段（如 URI）只是下游工具的输入指针，模型不必理解其内容，只需感知「存在这个可引用变量」。
  • 因此：结果默认入 workmemory；Runtime/DM 可在送模型前，按工具配置把对应值 mask 成 ${resultId.jsonpath}；模型后续只输出该引用，由 Runtime/DM 在调用前展开真值。

2. 方案原则

  • 默认入库工具返回结果默认写入 workmemory（分配 resultId）。
  • 入参回填Runtime/DM 在 invoke/exec 前，根据模型输出的引用解析并回填变量真值。
  • 查找顺序兼容优先：先查 resultDataList（全量工具返回），再查 dataForTool（部分工具已适配面）。
  • 短引用模型侧只持有/输出 ${resultId.jsonpath}，不复述长 value。

3. 关键点

  • 遵从性：输出短引用远比抄长串稳；mask 后可选空间更小。
  • 可见性分场景：不需理解的值可 mask；需推理的值可暴露，但仍用引用传参（Skill 约束）。
  • 解析无歧义：resultId 不含 .，用第一个 . 切开 id 与 jsonpath。
  • 兼容两套存储：resultDataList 兜底全工具；dataForTool 承接已适配工具。
  • 失败可感知：引用非法/未命中返回明确错误，避免把字面量 ${...} 误传下游。

4. 逻辑架构 · 完整流程

① 工具返回 工具执行完成，产出结果（可含 URI / 大字段）
② 写入记忆 默认写入 workmemory，生成 resultId；落入 resultDataList，必要时同步 dataForTool
③ 送模前处理 按工具配置：需屏蔽的字段用 ${id.path} mask；需理解的字段保留/摘要
④ 模型出参 下一工具入参填写 ${resultId.jsonpath}，不抄长值
⑤ 解析回填 invoke/exec 前：校验 → 查 resultDataList → 再查 dataForTool → 替换真值
⑥ 真正调用 用展开后的 args 执行工具；成功则再次入库，形成闭环

边界：Model 只产引用 · Runtime/DM 负责入库、mask、解析回填 · Workmemory 按 resultId 存结果 · Tool Runtime 只消费真值。

场景① 模型不需要看 value

做法：Runtime/DM 在送模型前，按工具配置把字段值直接 mask 为 ${resultId.jsonpath}。模型只需感知变量存在，后续原样引用即可。
  • 典型：fileUri、objectId、authorizeUrl 等「指针型」字段。
  • 遵从：几乎只能输出该引用串，抄错长 URI 的路径被关掉。
  • Token：回灌接近常量，省得最多。
真值fileUri = "https://…/very/long/path?…"
送模fileUri = "${a1b2c3d4.fileUri}"（已 mask）
模型analyze({ fileUri: "${a1b2c3d4.fileUri}" })
DMresultDataList → 命中 → 回填真实 URI → 调用

场景② 模型需要看 value

做法：把 value（或摘要）交给模型做推理；同时用 Skill 约束：对应入参必须填 ${resultId.jsonpath}，禁止把长 value 再贴回工具参数。
  • 典型：要读正文/结构化字段才能决定下一步，但下游仍要原值。
  • 遵从：「看」与「传」分离——推理用真值，传参用引用。
  • Token：回灌有内容成本；传参链路仍避免二次复制长串。
送模text="血糖偏高…" · 可引用 ${e5f6a7b8.text}
Skill入参 content 声明必须使用引用
模型report({ content: "${e5f6a7b8.text}" })
DM解析回填 text 真值后调用 report

5. 生命周期

  1. 创建：工具返回成功 → 分配 resultId → 写入 workmemory（resultDataList；按需 dataForTool）。
  2. 暴露：场景① mask 为引用串；场景② 可见/摘要 + 告知可引用路径。
  3. 引用：模型输出 ${resultId.jsonpath}。
  4. 回填：invoke/exec 前解析；先 resultDataList，再 dataForTool。
  5. 失效：会话结束 / TTL / 显式清理；未命中则明确报错回模型。

6. 收益

  • 时延：Input Token 下降，串行工具链更快。
  • 遵从：短引用 + 可选 mask，减少抄写错误。
  • 正确：真值由 Runtime/DM 注入，避免截断/篡改。
  • 兼容：resultDataList 覆盖全工具；dataForTool 承接存量适配。
  • 演进：jsonpath 可从简单字段名逐步放开；与批/并行调用共用同一缓存。

7. 边界

  • 只在工具 入参 侧解析引用；工具输出侧不展开引用。
  • resultId 仅字母数字；用首个 . 分隔 jsonpath。
  • 一期可先支持简单字段名，再扩展受限 jsonpath。
  • 与 HTML Preview 等渲染能力正交，可独立落地。
一句话：结果默认入 workmemory；不需理解则 mask 成引用；模型只输出 ${resultId.jsonpath}；Runtime/DM 在 invoke 前按 resultDataList → dataForTool 回填真值。
