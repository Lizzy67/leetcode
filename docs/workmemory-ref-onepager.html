Workmemory 引用方案 · 一页纸

目标：降低多轮工具调用的 Input Token，同时提升模型对「传参」的遵从性
语法：${resultId:param}
resultId = 字母数字 · param = 简单字段名

1. 背景

  • 串行工具链中，上一步结果（尤其 URI/大字段）若整段回灌模型，Input Token 膨胀 → 时延上升。
  • 要求模型「原样抄长字符串」时，易出现截断、改写、漏字符，遵从性差。
  • 需要：结果默认缓存 + 引用传参；模型只说「用哪条结果的哪个字段」，由 DM 展开真值。

2. 方案原则

  • 默认缓存工具成功结果写入 workmemory，无需额外 save 工具。
  • 引用只在入参DM 在 invoke/exec 前解析；输出不做引用展开。
  • 查表顺序先 resultData，再 dataForTool。
  • 短引用优先模型输出短 token，比复述长 value 更稳、更省。

3. 关键点（遵从性）

  • 降低抄写负担：模型只需输出 ${id:field}，不必复述长 URI/正文。
  • Skill 声明可引用：参数标 x-ref，把「该写引用」写进契约，而不是口头希望。
  • 两种可见性：不看 value → 直接 mask；要看 value → Skill 仍约束「工具入参必须用引用」。
  • 校验失败可重试：引用非法/未命中时返回明确错误，引导改写引用而非瞎猜字符串。

4. 逻辑架构 · 完整流程

① 工具执行 Tool 跑完返回结果（含 URI/大字段等）
② DM 入库 按默认策略写入 workmemory：resultData / dataForTool，生成 resultId
③ 回灌模型 按场景：mask 或带 preview；附带「可引用字段」提示
④ 模型出参 下一工具参数写 ${resultId:param}，不抄长值
⑤ DM 解析 校验语法 → 查 resultData → 回退 dataForTool → 替换真值
⑥ 真正调用 用展开后的 args 调工具；成功则再入库，闭环

组件边界：Model（只产引用）→ DM（缓存 + 解析 + 编排）→ Workmemory（按 resultId 存两面）→ Tool Runtime（只收真值）。 Client 面可选只暴露摘要；Runtime 面可服务端私有。

场景① 模型不需要看 value

策略：对变量值做 mask / 省略；模型上下文里只保留 resultId、字段名、类型与长度提示。
  • 适用：下一步工具只要「指针」（如 fileUri、objectId），模型无需理解内容。
  • 遵从性：可选空间极小——几乎只能输出 ${resultId:param}。
  • Token：回灌几乎为常量级，省得最多。
回灌resultId=a1b2… · fields=[fileUri] · fileUri=<masked len=180>
模型analyze(fileUri="${a1b2c3d4:fileUri}")
DM展开为真实 URI 后调用 analyze

场景② 模型需要看 value

策略：把 value（或摘要）给模型做推理；但通过 Skill 约束：标了 x-ref 的入参必须填引用，禁止把长 value 再贴回工具参数。
  • 适用：要读正文/结构化字段才能决定下一步，但仍要用原值调下游工具。
  • 遵从性：推理用真值；传参用引用——「看」与「传」分离。
  • Token：回灌有内容成本；传参链路仍避免二次复制长串。
回灌text="血糖偏高…" · resultId=e5f6… · refFields=[text]
Skillreport.content: { "x-ref": true } → 必须引用
模型report(content="${e5f6a7b8:text}") ← 即使已看过 text

5. 生命周期

  1. 创建：工具成功返回 → DM 分配 resultId → 写入 resultData（必要）/ dataForTool（按需）。
  2. 暴露：场景① mask；场景② 可见/摘要 + 声明可引用字段。
  3. 引用：模型输出 ${resultId:param}；DM 解析替换。
  4. 失效：会话结束、TTL、显式清理、或同 id 被策略覆盖。
  5. 失败：语法错 / 未命中 / 字段不存在 → 明确错误回模型，不静默吞掉。

6. 收益

  • 时延：Input Token 下降 → 串行工具链更快。
  • 遵从：短引用比抄长串更稳；Skill 把规则固化。
  • 正确性：真值由 DM 注入，减少截断/篡改。
  • 成本：少传重复大字段，账单与上下文窗口双省。
  • 演进：字段名可平滑升到受限 jsonpath；并行/批调用可复用同一缓存。

7. 非目标 / 边界

  • 不做 save_as_variable 类额外工具。
  • 输出侧不解析引用；只处理工具入参。
  • 一期 param 为简单字段名，不做任意 jsonpath。
  • 本方案默认工具结果无 Secret；若未来有敏感字段，再叠加脱敏策略。
  • 与 HTML Preview 等渲染能力正交，可独立落地。
一句话：缓存结果、引用传参；不看则 mask，要看也仍用引用——用 Skill 锁遵从，用 DM 保真值。
