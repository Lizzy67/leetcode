Workmemory 引用方案 · 一页纸

语法 ${resultId.jsonpath} · resultId = 8 位十六进制（无 .）

1. 背景

  • 大结果照抄回下一工具 → 遵从性差、Input Token 高。
  • URI 等只需当下游入参，模型感知变量即可。
  • 送模前按配置 mask 成 ${resultId.jsonpath}。

2. 方案原则

  • 工具返回默认写入 workmemory。
  • invoke/exec 前按引用解析回填。
  • 查找：resultDataList → dataForTool。

3. Mask 配置

  • 通用默认：字段名命中 fileUri / fileId / objectId / *Url 等指针型 → 默认 mask。
  • 工具覆盖：单工具可增删 mask 字段（要读的正文勿进默认名单）。
  • 优先级：工具配置 > 通用默认。

4. 流程

① 返回工具产出结果
② 入库写 workmemory + 生成 resultId
③ 送模通用/工具配置 mask
④ 出参模型写 ${id.path}
⑤ 回填resultDataList → dataForTool
⑥ 调用真值执行，再入库

场景① 不看 value

  • 默认/工具 mask；模型只感知变量。
  • 典型：fileUri、fileId。
${a1b2c3d4.fileUri} → 原样引用 → DM 回填

场景② 要看 value

  • 可见/摘要供推理；传参仍用引用（Skill + Prompt）。
  • 「看」与「传」分离。
可见 text → 入参 ${e5f6a7b8.text}

5. resultId 设计

  • 为何不直接用 toolCallId：供应商签发、长度常 32+、格式不一（可能含 _/-），直接进 ${...} 费 token、难统一解析。
  • 分工：toolCallId = 对内关联键；resultId = 对模短引用（8 位 [0-9a-f]）。入库时存映射 resultId ↔ toolCallId。
  • 统一算法（推荐）：DM 唯一生成；resultId = hex8(FNV-1a-64(toolCallId))（会话级存储可再混 sessionId）。禁止各系统各自 UUID[:8] 随机截断。
  • 会话内调用量远低于 32-bit 碰撞阈值；需要更稳可升 12 位 hex。

6. 生命周期 / 约束序

  1. 创建：返回 → 算 resultId → 入库并挂 toolCallId
  2. 暴露：默认/工具 mask，或可见 + 可引用路径
  3. 引用：模型输出 → invoke 前展开
  4. 失效：会话结束 / TTL；未命中报错

约束序：mask > Skill > SystemPrompt。Prompt 为软兜底（token>12 禁照抄）。

7. SystemPrompt 建议文案（可直接嵌入）

作用范围：工具入参的「照抄上一步结果」；用户原话/可独立确定的字面量仍直接填。
# 工具结果引用约定

当某个工具参数的取值来自上一步某条工具结果中的字段时，不要复述、改写或猜测该值，请输出引用占位符，由系统在执行前回填真实值。

## 写法
`${<resultId>.<字段路径>}`

- `<resultId>`：从上下文中对应 role=tool 结果读取的 resultId（仅字母数字）。必须照抄上下文，禁止编造。
- `<字段路径>`：该结果内的字段路径，支持点号嵌套，例如 `entityId`、`data.fileUri`。
- 整个参数值必须等于占位符本身：不要省略 `$` / `{` / `}`，不要前后拼接其它文字。

## 何时必须用引用
- 参数说明要求引用，或取值明确来自已有工具结果字段；
- 尤其当该值较长（建议：超过约 12 个 token，如 URI、fileId、大段文本）时，禁止照抄原文，改输出引用。

## 何时仍填字面值
- 取值来自用户原话，或可独立确定的短信息（如相册名、数量、开关等），且并非某一工具结果字段的拷贝。

具体该引用哪个字段，以各工具/方法的参数说明为准。
通用 mask（fileUri/fileId…）+ 工具覆盖 → 短 resultId 对模、toolCallId 对内 → Prompt 禁长值照抄 → invoke 前 resultDataList → dataForTool 回填。
